# Development Process

1. leader 创建 run ID，产品分析师固定输入版本并建立需求追溯矩阵。
2. 架构、UX、测试与安全并行设计；所有假设进入开放项。
3. 独立评审者执行 G1，leader 记录取舍后调度者才创建可执行工作包。
4. 工程师在隔离分支/工作区实施；工作包完成时附上代码审查和测试证据。
5. QA、安全和集成人员在与版本绑定的环境执行 S4；G2 决定回流或发布候选。
6. 发布工程师组装可复现制品、部署/回滚计划并请求变更授权。
7. 获得 G3 的明确授权后，发布工程师只向批准的预发布目标部署，QA 执行冒烟与验收。
8. leader 消费证据并形成最终 handoff；未满足项如实保留为 partial/blocked。

调度者每次状态变化只更新计划与依赖，不得充当审批者。所有回流均须含缺陷 ID、证据、目标阶段和轮次。
