# Codex adapter mapping

| Core requirement | Mapping | Status |
| --- | --- | --- |
| Sealed work order and allowlist | Local workspace files plus SHA-256 verification before tool use | tool |
| Ordered bounded-skill calls | Parent Agent creates a fresh task with the registered skill only after prior completion passes | native |
| Fresh-context semantic execution | Child receives sealed inputs and owner instructions, never a parent-written answer | native |
| Isolated HQ2 tasks | Separate Agent contexts with disjoint allowlists and identities | native |
| External author event | User response is materialized by the parent as a sealed event | manual |
| Immutable state and revision artifacts | Append-only files generated by portable core | tool |
| Composite publisher | Portable deterministic publisher invoked by parent | tool |
| Agentic qualification evidence | Task identities, transcripts, immutable refs and independent reviews validated by the qualification gate | tool + native |
| Unsupported runtimes | No fallback or semantic emulation | unsupported outside Codex |

Codex may orchestrate child agents, but no child may write run state, route itself, silently broaden its allowlist or treat chat as a canonical input. The parent must follow `operation.md` and consume only `stage-result.json` after deterministic validation. If fresh tasks, transcript export or identity separation are unavailable, execution must stop as unsupported; it may not degrade to a same-context simulation.
