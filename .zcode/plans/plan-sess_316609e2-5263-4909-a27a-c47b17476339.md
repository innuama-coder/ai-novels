# ai-novels 仓库重构：根目录收敛为 duanxian/ + engine/

## Context

仓库现状：1281 个跟踪文件平铺在 9 个顶层目录，小说素材（断线）与工作流引擎（skills/harnesses/校验器）混放，docs/superpowers 等目录双重身份，另有 47 个与两者无关的 KUNORA.ai 产品 UI 资产。目标：根目录只留 `duanxian/`（断线构思与设计）和 `engine/`（工作流、技能、构建器）两个子目录。用户已确认：①目录名 duanxian/+engine/；②删除 KUNORA 资产；③先合并 dev 再重构。

关键洞察（探索结论）：引擎内部全部使用「仓库根相对」引用（`parents[3]` 找根、`docs/ai-novel-workflow/contracts` 契约真源、importlib 前缀 `harnesses.`）。**因此 engine/ 内部保持旧根布局整体平移**（engine/skills、engine/docs/ai-novel-workflow、engine/docs/superpowers/specs…），引擎内部 90% 引用无需改动；真正要改的是断线侧构建器、validate_design_tasks.py 双根、根相对文档链接。
