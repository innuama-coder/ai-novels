# HP1 standard operating procedure

1. Load only `work-order.json`; validate common schema, exact HP1 owner/version/hash, mode, state/input-gate equality, empty unresolved projection and no pre-existing output.
2. Resolve each allowlisted role inside the workspace and verify its SHA-256. Reject duplicate, missing or extra roles.
3. Verify the ordered eight-stage upstream artifact triples against the work-order.
4. For each package, validate common manifest/completion schemas, public ready profile, complete manifest closure, completion bindings, current run/revision readiness and passing validation.
5. Require HQ1 `pass` with zero findings; require identical HB0-derived authority partitions across design stages.
6. Copy all seven design models, including the complete HD1 chapter-definition architecture, and the HQ1 review byte-for-byte into `canonical-models/`.
7. Project HB0 registry/source-index entries into immutable baseline controls; build a global stable-ID cross-index and reject collisions.
8. Aggregate HDD dispositions with the closed decision table; preserve open values as canonical JSON plus value hash.
9. Read HK1 `LWR-*` requirements, validate every required field and produce the suffix-preserving `LWK-*` bijection.
10. Build trace rows from explicit source and decision references; require every source to resolve to an HB0 source-control entry and every decision to exist.
11. Emit the machine package, Markdown views, execution record and validation; validate every HP1 schema.
12. Build a manifest over the exact ready content profile, then completion over manifest/validation/canonical artifacts, then package-external result.
13. Derive character and environment entity sets only from the sealed typed source-index collection locators (`/profiles/{index}` and `/environments/{index}`), or from the exact single-object `/value` discriminator used by generic fixtures. Reject a missing, duplicate, malformed or control-unbound entity index. Do not treat relationship, freedom, demand or functional-zone records as entities.
14. Atomically commit the package and result.
15. Independently reload the work-order, regenerate into a temporary location using canonical final refs, compare every byte and validate completion bindings.
16. Return `0/ready`, `2/blocked`, or `1/runtime error`. Never mix ready and blocked profiles.

## Block immediately when

- an upstream is stale, malformed, incomplete, non-ready, profile-open or hash-invalid;
- HQ1 does not pass cleanly;
- authority partitions differ;
- stable IDs collide or trace sources/decisions do not resolve;
- an HDD coverage/disposition combination falls outside the closed rule;
- an LWR is missing/incomplete, begins with `LWK-`, duplicates or collides;
- regenerated bytes differ.
