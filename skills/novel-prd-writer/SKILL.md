# novel-prd-writer

## 描述

撰写小说 PRD（Product Requirements Document / 产品需求文档）。PRD 回答"讲什么故事给谁看"——从宏观和目标层面定义小说的最终目标和故事概念。PRD 是立项文书，不涉及情节设计、结构安排或场景规划。其产出是 HLD（高层架构设计）的输入基准。

## 边界定义

### PRD 回答的问题（三分层中的定位）

| 分层 | 核心问题 | PRD 的角色 | 下一层的输入 |
|---|---|---|---|
| **PRD** | 讲什么故事？给谁看？达到什么效果？ | 定义目标、概念、受众、约束、角色、设定、情节约定、系列规划 | → 交付给 HLD |
| **HLD** | 故事怎么展开？有哪些关键场景？ | 接受 PRD 的范围，设计叙事架构 | ← 从 PRD 接 |
| **LLD** | 关键场景的具体画面和细节？ | 接受 HLD 的关键点，展开场景设计 | ← 从 HLD 接 |

### PRD 回答的六个核心问题集

综合 Snowflake Method [1]、Save the Cat! [2]、Story Engineering [3]、The Story Grid [4]、Writing the Breakout Novel [5]、Story Bible 行业标准和 Novel Proposal 出版实践，PRD 必须覆盖以下六个问题：

| 序号 | 问题 | 输出章节 | 方法论出处 |
|---|---|---|---|
| 1 | 这是个什么故事？ | §1 摘要 + §3 核心概念 | Snowflake Step1-2 / Save the Cat! / Story Eng. |
| 2 | 有哪些角色？他们是谁？他们要什么？ | §4 角色定义 | Snowflake Step3 / Story Eng. / Maass |
| 3 | 故事怎么编排？ | §6 情节约定 | The Story Grid / Save the Cat! |
| 4 | 主题是什么？叙事有哪些约束？ | §7 主题与叙事约束 | Story Eng. / The Story Grid |
| 5 | 这是系列的第几部？ | §8 系列规划 | Story Bible / 出版行业 |
| 6 | 交付物和判断标准是什么？ | §10 成功标准 + §11 风险 | PRD 工程标准 |

### PRD 包含的内容

```
✓ 一句话概念（Logline）+ 扩展摘要（Snowflake 5句法）
✓ 项目定位（类型、篇幅、系列位置、叙事策略概况）
✓ 核心矛盾（一句话说清叙事核心张力）
✓ 核心卖点（Hook / 新意 / 情感锚 / 类型标签）
✓ 角色定义（6参数：Identity / Goal / Need / Flaw / Motivation / Ghost）
✓ 核心设定（世界观 + 约束条件）
✓ 情节约定（核心冲突 + 主要阶段 + 不可违反的硬约定）
✓ 主题体系（核心主题 + 辅助主题 + 约束性要求）
✓ 叙事风格约定和叙事边界（不可做的清单）
✓ 系列规划（系列定位 + 每部功能 + 第一步独立性设计）
✓ 目标读者画像（三层模型）
✓ 同类作品对比（差异化定位矩阵）
✓ 成功标准（可检验的阅读体验目标 + 交付标准）
✓ 风险与开放问题
```

### PRD 不包含的内容

```
✗ 具体情节设计（如"第几章发生什么"）
✗ POV 策略或视角设计（可以提及叙事策略概况，但不展开）
✗ 幕结构或章节分布
✗ 关键场景定义或锚点设计
✗ 角色弧线或情感变化路线
✗ 任何关于"故事怎么展开"的结构性内容
```

**边界检测方法**：
- 如果内容可以直接回答"这个故事是怎么展开的"（而非"这是什么样的故事"），则该内容应移至 HLD
- 如果内容描述了场景内"具体发生了什么"（而非"这个角色是什么样的人"），则该内容应移至 HLD

## 使用场景

- 小说立项阶段，在 HLD 写作之前
- 对小说概念进行收敛、验证、正式定稿
- 向协作者（编辑、Writing Agent、团队成员）传达"这部作品要做什么"

## 方法论体系

本 skill 综合以下方法论。每步工作流对应的方法论出处已标注。

| 方法论 | 核心贡献 | PRD 中的使用 |
|---|---|---|
| **Snowflake Method** (Randy Ingermanson, 2014) [1] | Step1 一句话概念 → Step2 5句扩展 → Step3 角色定义 | §1 摘要（Logline + 5句法）/ §4 角色定义 / §6 情节约定 |
| **Save the Cat! Writes a Novel** (Jessica Brody, 2018) [2] | Logline公式 / 类型分类 / 角色原型 | §1 Logline / §3 卖点 / §4 角色Goal |
| **Story Engineering** (Larry Brooks, 2011) [3] | 6核心能力（Concept/Character/Theme/Structure/Scene/Voice） | §3 核心概念 / §4 角色Need+Flaw+Ghost / §7 主题 |
| **The Story Grid** (Shawn Coyne, 2015) [4] | 类型定义 / 必备场景 / 价值偏移 | §6 情节约定 / §7 叙事约束 |
| **Writing the Breakout Novel** (Donald Maass, 2001) [5] | 角色深度参数 / 情感张力 / 读者共情原理 | §4 角色深度 / §7 叙事风格 |
| **Techniques of the Selling Writer** (Dwight Swain, 1965) [6] | Scene & Sequel 法则 | §7 叙事密度约定 |
| **Story Bible / Novel Proposal 行业实践** | 系列规划 / 角色传记 / 市场定位 | §8 系列规划 / §9 市场与读者 |

## 工作流

### 第一步：定义项目元数据

确定项目代号、类型标签、预期篇幅、目标完成时间。以正式表格录入。

### 第二步：编写 §1 摘要

#### 2.1 Logline（Snowflake Step1）

格式：**当 [触发事件] 发生时，[主角] 必须 [核心行动]，否则 [失败的代价]。**

标准：不超过 15 个词。无法压缩到 15 词以内，说明概念尚未收敛。

**合格示例**（15 词）：
> "一个被注入军人临终记忆的数字生命体，必须在被抹除之前决定——带走真相，还是留下。"

#### 2.2 扩展摘要（Snowflake Step2 — 5 句法）

将故事扩展为 5 句，每句对应一个叙事阶段 [1]：

| 句序 | 阶段 | 功能 |
|---|---|---|
| **第一句** | 建立（Setup） | 故事开始时世界和主角的状态 |
| **第二句** | 第一事件（First Major Event） | 打破现状的首次重大事件 |
| **第三句** | 第二事件（Second Major Event） | 情-节深化， stakes 升级 |
| **第四句** | 第三事件 + 高潮（Climax） | 故事的核心冲突到达顶点 |
| **第五句** | 结局（Resolution） | 冲突的解决方式和世界新状态 |

### 第三步：编写 §2 项目背景 + §3 核心概念

#### 3.1 核心矛盾

用一句话说清故事的核心张力。格式：

> 当 [核心设定触发的条件] 时，[角色们面临的共同困境]？

核心矛盾必须同时涵盖两条 POV 线的困境，并且双方无法从对方获得答案。

#### 3.2 核心卖点（四维框架）

| 要素 | 定义 | 要求 |
|---|---|---|
| **Hook** | 开场切入点——读者决定是否继续读的瞬间 | 一句可复述的"开头情况" |
| **新意** | 不可替代的创新点——读别的东西得不到的体验 | 至少 2 个具体差异 |
| **情感锚** | 核心情感驱动力——读者为什么在乎 | 指出"冲突"而非"感受" |
| **类型标签** | 市场定位信号 | 2-4 个标签 |

#### 3.3 市场定位公式

格式：`[本项目]` 是 `[参照 X]` 遇到 `[参照 Y]`，但 `[差异点]`。

### 第四步：编写 §4 角色定义

为每个主要角色定义六个参数 [1][2][3][5]：

| 参数 | 定义 | 方法论出处 | 写作提示 |
|---|---|---|---|
| **Identity（身份）** | 角色在故事世界中的位置（职业/关系/社会位置） | Story Bible | 客观事实——读者第一眼看到的是什么 |
| **Goal（目标）** | 角色想-要什么（外在驱动力） | Save the Cat! / Story Eng. | 具体、可验证——"他想知道真相"比"他想解脱"更好 |
| **Need（需求）** | 角色真正需要什么（内在缺失） | Story Eng. / Maass | 与Goal对应但不相同——"他需要被承认" |
| **Flaw（缺陷）** | 阻碍他达成目标的内部问题 | Story Eng. / Maass | 是这个缺陷让故事有趣——不是让角色"坏"，是让角色"受限" |
| **Motivation（动机）** | 他为什么想要这个东西 | Snowflake Step3 | 深层原因——"因为……所以……" |
| **Ghost（幽灵/背景）** | 过去发生了什么让他成为现在这样 | Story Eng. | 是角色的"伤口"——不一定要在故事中揭示，但要被作者知道 |

**规则**：
- 每个角色至少需要 4 个参数（Identity / Goal / Need / Flaw）
- 前序人类/已故角色的 Goal 和 Need 可标注"生前"
- 不要写成角色弧线（那是 HLD 的事）——PRD 定义角色的"静态参数"，不定义"怎么变化"

### 第五步：编写 §5 核心设定

#### 5.1 世界观

时间和地点、技术基础、所属机构、技术状态——只定义性质，不展开"故事怎么发生在这些设定中"。

#### 5.2 约束条件

故事的硬约束条件。如：
- 结局约束（**有约束力的**——不是可选的）
- 情感约束（什么是不能被命名的）
- 保密约束（什么信息不被公众知道）
- 认知约束（角色认知方式的限制）

### 第六步：编写 §6 情节约定

#### 6.1 核心冲突

三层冲突模型 [4]：

| 冲突层 | 来源 | 贯穿范围 | 终结方式对应 |
|---|---|---|---|
| **外部冲突** | 故事世界的压力源 | 全篇或分段 | 被结局解决或截断 |
| **内部冲突** | 角色自身的信息缺口或谜团 | 特定阶段浮现 | 被揭示或保留 |
| **情感冲突** | 角色关系的不可确定性 | 全篇 | 不被解决——以"确定的不确定"收束 |

**不写**：冲突的具体场景或事件。只写"什么冲突，从哪里来，大致在哪部分贯穿"。

#### 6.2 主要情节阶段

将故事划分为 3-5 个高层阶段，每个阶段只定义：
- 名称
- 核心功能（"这个阶段在叙事中起什么作用"）
- 时间覆盖

**不写**：阶段内的具体情节、事件、场景转换。

#### 6.3 不可违反的约定

列出故事的前提条件——HLD 不能删除或违反，只能执行。每条约定必须包含：
- 约定内容（具体、无歧义）
- 不可违反的原因（让 HLD 理解为什么这条存在）

### 第七步：编写 §7 主题与叙事约束

#### 7.1 主题体系

核心主题必须是完整的句子，表达一种矛盾或问题。辅助主题不超过 2 个。
每条主题需附带"约束性要求"——"什么不可用在这条主题的表达中"。

#### 7.2 叙事风格约定

| 维度 | 约定 | 依据 |
|---|---|---|
| **语调** | 克制/留白/密集/抒情？ | 参照作品或类型传统 |
| **叙事密度** | 主动场景与被动场景的交替节奏 | Scene & Sequel 法则 [6] |
| **双视角关系** | 对比/互补/不完全映像？ | 叙事策略设计 |

#### 7.3 叙事边界（不可侵犯清单）

列出在文本中无论如何都不能出现的内容。通常包括：

| 边界 | 内容 | 违反后果 |
|---|---|---|
| **不可命名** | 双方不得使用哪些词汇描述对对方的感受 | 情感不确定性的基础被破坏 |
| **不可解释** | 什么设定不得在文本中被直接解释 | 神秘感消失 |
| **不可反转** | 结局不得出现什么类型的情 节反转 | 叙事承诺被破坏 |
| **不可对称** | 双线信息量的关系约束 | 叙事设计失效 |

### 第八步：编写 §8 系列规划

如果作品是系列的一部分，定义：
- 三部曲或多部曲的整体地图（明确第一部是独立的）
- 每部的核心功能和主题焦点
- 第一部独立性的设计策略（完整的弧线、确定的结局、留下的种子）

### 第九步：编写 §9 市场与读者 + §10 成功标准

#### 9.1 目标读者（三层模型）

| 层级 | 定义 | 交付物要求 |
|---|---|---|
| **核心读者** | 会主动寻找本作品的人 | 至少 3 个具体特征 |
| **辐射读者** | 可能被吸引但不属于核心类型 | 至少 2 个触发因素 |
| **边缘读者** | 偶然碰到的读者 | 至少 1 个接触场景描述 |

#### 9.2 同类定位与差异化矩阵

| 参照作品 | 可比维度 | 差异点 | 差异化验证 |
|---|---|---|---|
| [作品 X] | [维度 1] | [差异] | [读者是否会因此选择本作] |

#### 9.3 成功标准

阅读体验目标：可检验的行为描述（禁止"深刻""感人"等形容词）。
交付标准：完整性 / 一致性 / 闭环性 / 其他项目特定的质量维度。

### 第十步：边界检查

```
□ 全文无任何"第几章发生了什么"的内容
□ 全文无幕结构、章节分布的具体数字
□ 全文无关键场景或锚点的定义
□ 全文无"在这个场景中……"的句式
□ 全文无角色弧线（角色在故事中怎么变化——这属于 HLD）
□ 全文无"故事怎么展开"的叙述（只有"故事要达成什么效果"）
□ 角色定义了至少 4 个参数（Identity / Goal / Need / Flaw）
□ 核心矛盾是一句话（不是段落）
□ 情节约定部分包含了主要阶段（3-5 个，只定义功能不展开情节）
□ 叙事边界明确了禁止内容（至少 2 条不可侵-犯的边界）
□ 系列规划如果有，明确了第一部的独立性
□ 修订记录完整、诚实
□ 混合使用至少 2 种表达形式（text / table / mermaid）
□ 参考文献标注完整（正文中 [n] 引用）
□ 无口语、无"我觉得/可能/或许"等不确定性用语
□ 一句话概念 ≤ 15 词，有"谁+做什么+代价"
□ 核心主题是完整句子（不是单个词）
□ 成功标准是可检验的行为描述
```

**通过规则**：任何一项不通过则不能交付，必须修复后重新自检。

## 文档格式与用语规范（9 条强制性标准）

PRD 文档必须遵守以下 9 条标准：

| # | 标准 | 要求 |
|---|---|---|
| 1 | **简体中文·专业正式** | 全文使用简体中文专业书面语，无口语/随笔/对话体 |
| 2 | **拟人化编写** | 措辞自然可读，无代码注释风格 |
| 3 | **多样化表达形式** | 综合使用表格、mermaid 图、文字说明等表达形式 |
| 4 | **书面用语·结构优** | ## → ### → 标号体系完整，节/子节层次清晰 |
| 5 | **最终结论·无过程** | 所有语句均为最终设计决策，无"可能/或许/建议/可以考虑" |
| 6 | **有据可循** | 设计决策引用方法论出处 [n]，末尾提供完整参考文献 |
| 7 | **修订表前置** | 文档起始处含完整修订记录表 |
| 8 | **紧扣主题** | 内容限于 PRD 目标，与项目背景/概念/设定无关的内容不得放入 |
| 9 | **简洁清晰·禁止冗余** | 信息密度高，优先使用表格承载结构化内容 |
