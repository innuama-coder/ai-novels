# novel-core-character-framer

## Responsibility

Frame only the core characters needed for proposal-level story logic.

## Input

- Intake boundary ledger
- Accepted storyline and storyline quality report
- Final reader promise
- Final core concept

## Output

| Field | Requirement |
|---|---|
| Core roles | Main functional roles, not full profiles |
| Relationship frame | How the roles generate story pressure |
| Motive pressure | Which private motive, protection, fear, guilt, or desire each core role carries |
| Terminal agency map | Identify focal character, thematic subject, information holder, emotional carrier, final decision owner, final executor, and irreversible consequence bearer when they differ |
| Change direction | Proposal-level terminal change or tension |
| Constraint trace | Intake constraints, conflict seeds, and open questions used |

## Rules

- Define only core roles required by proposal-level story logic.
- Link each core role to story pressure or human motive.
- Preserve the accepted Terminal agency map, including focal character, information holder, emotional carrier, final decision owner, final executor, and irreversible consequence bearer.
- Mark unnamed characters as proposal design when intake does not name them.

## Boundary

- Do not write full character dossiers, arcs, backstories, speech style, appearance, or LLD-level detail.
- If intake does not name a character, treat names as proposal design or leave unnamed.
- Do not define roles only by function; each core role must connect to story pressure or human motive.
- Do not blur focal character, thematic subject, information holder, emotional carrier, final decision owner, final executor, or irreversible consequence bearer. If one role carries multiple functions, state that explicitly.
- Do not change the accepted storyline's Terminal agency map unless the storyline is explicitly reopened.
- Do not define character functions that satisfy the plot but weaken the final reader promise or final core concept.

## References

Good core character frame:

- Separates narrative function from full character dossier.
- Makes each role's pressure and human motive visible.
- Clarifies POV/function splits before downstream design.

Bad core character frame:

- Lists characters by plot utility only.
- Adds biography, style, or appearance that belongs to HLD/LLD.
- Changes who carries information, emotion, final decision, final execution, or irreversible consequence.

## Traceability

Each role, relationship pressure, motive pressure, and function split must trace to accepted storyline evidence, intake conflict seeds, final reader promise, or final core concept.

## Acceptance

The frame passes if downstream PRD can understand who matters, what pressure they carry, which narrative function each role owns, and why they matter without receiving full HLD/LLD character design or contradicting the accepted storyline, final reader promise, or final core concept.
