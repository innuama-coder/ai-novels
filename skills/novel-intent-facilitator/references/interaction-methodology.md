# 意图访谈的方法论与落地规则

启动访谈前阅读本文件。它不是一份机械问卷；它说明为什么要先探索、再收敛、最后确认，从而把作者的意图转换成可交接的设计决定。

## 可执行的访谈检查表

### 提问前

- 写下本轮唯一的学习目标，以及本轮明确不讨论的事项。
- 列出已经确认、仅为 Agent 推断、仍然开放的信息；不要把推断伪装成作者意图。
- 从最容易描述的体验或已有片段开始；信息不足时先求理解，不急于补全设计。

### 提问中

- 按“开放 → 澄清 → 收敛 → 确认”推进：先让作者自述，再追问含义，最后才提供候选。
- 一次只问一个决定；一轮最多三道短问题。复合问题拆开处理。
- 使用中性语言和作者原话。不要在问题里预设主题、质量判断或答案。
- 候选最多三个，且须在一个真正的控制点上不同；每项写明对故事方向的影响，并保留“均不合适，请用自己的话重述”。
- 候选是帮助比较的脚手架，不是替作者做决定。作者提出更重要的新线索时，可追问一次，然后回到当前目标。

### 确认前与确认后

- 复述“你决定的是 X；这意味着开发阶段会 Y；暂不决定 Z”，再要求明确确认。
- “可以”“差不多”“你看着办”只可记为暂定，不可写成已确认；有矛盾的硬约束则标为阻塞。
- 记录作者原话、Agent 推断、提出的问题、确认措辞和结果，以便后续 skill 判断结论的来源与置信度。

## 常见反例

| 不佳问法 | 为什么无效 | 改写方式 |
| --- | --- | --- |
| “你是不是想写一个关于 AI 孤独的感人故事？” | 预设主题和情感评价，容易诱导同意。 | “在这个设定里，你最希望读者持续面对什么问题？” |
| “主角是科学家还是军人，世界观和结局怎么设定？” | 混合多个控制点，回答无法归因。 | “先只决定：主角进入冲突时最关键的身份位置是什么？” |
| “选 A 还是 B？” | 没有取舍信息，可能只是伪选择。 | “A 会把重点放在……；B 会把重点放在……；都不合适也可以重述。哪一个更接近？” |
| “明白了吗／都可以吗？” | 不能核验决定，也没有记录其影响。 | “确认一下：你决定保留开放结局，因此开发阶段不写真相揭露，对吗？” |
