# 呈现一致性审查契约

## 审查对象

以 P1 为唯一构思本体，以 H1-A plan 的 source inventory 和可见元素集合为审查范围，
以候选 `human-review-report.json` 为呈现对象。H1-B 样章是非权威体验证据，不参与
构思事实合并。

## 五个维度

1. `author_control_fidelity`：作者锁定、禁止项、开放项和授权边界没有改变。
2. `world_story_character_fidelity`：世界、故事线、事件和角色的结论、关系及因果没有改变。
3. `omission_and_emphasis_fidelity`：十分钟压缩没有删除会改变判断的限定，也没有放大支持性信息。
4. `fragment_authority_boundary`：样章只实例化已授权控制，不建立新的跨场景事实。
5. `review_decision_integrity`：评审问题没有偷换批准范围，允许决定仍为批准、修改或否决。

## 逐元素判断

每个默认可见元素必须提交：

- 元素 ID 和候选内容哈希；
- 与 plan 完全相同的 source anchor 集合；
- 一个不依赖流程术语的故事专属语义判断；
- 至少一处候选报告中的精确引文；
- 三项否定检查：无关键遗漏、无矛盾、无权威升级；
- `faithful` 或仅对样章使用 `non_authoritative_sample`。

来源覆盖只能回答“读过什么”，不能回答“是否说对”。审查必须解释呈现如何保持来源
中的条件、边界和关系；“字段齐全”“哈希一致”“符合 schema”均不是合格的语义理由。

## 阻断条件

- 将 provisional/open 写成确定事实；
- 改变因果方向、人物动机、事件结果、组织权限或世界失败条件；
- 为简洁删除会改变作者判断的例外或代价；
- 样章新增权威背景、规则、关系或结局；
- 评审问题批准范围大于 P1 与样章实际呈现范围；
- 审查者与任一呈现生成任务身份相同。
