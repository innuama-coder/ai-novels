# HR1 Input and Output Contract

## Input gate

Accept only a sealed harness work order for `stage=HR1`, exact owner `novel-hld-rhythm-continuity-architect`, and `mode=forward|return_resolution`. Ordered upstream is exactly `[HB0,HA1,HS1,HC1,HI1]`.

Required content is the HB0 control/source index; HA1 structures and chapter shells; HS1 segments, connections, convergence, and event placement; HC1 arc/relationship/choice state changes; HI1 POV, knowledge, suspense, and reveal/payoff architecture; authorized world, environment, and event source objects; current state and bindings. Read only the input-gate allowlist. HR1 may read non-quality domains registered by the frozen source-access matrix, never `quality`.

Validate owner, run, revision, state, completion order, hashes, return and revision-plan bindings before interpreting story content. Assess every unresolved projection before candidates.

## Canonical output

`package/rhythm-continuity-architecture.json` is the sole content authority and contains common governance fields plus:

- `story_time_model`
- `narrative_order_map[]`
- `unit_duration_density[]`
- `space_transition_map[]`
- `parallel_synchronization[]`
- `pacing_curve[]`
- `tension_curve[]`
- `recovery_windows[]`
- `continuity_ledger[]`

Use `HTM-`, `HPC-`, and `HTN-` IDs. Every continuous state entry records subject, dimension (`location|time|knowledge|resource|permission|relationship|physical|emotional`), pre-state, change source, post-state, persistence interval, and release condition. Every movement records endpoints, world-authorized mechanism, minimum/maximum duration where known, permissions/resources, and affected concurrent tracks. Every analepsis/prolepsis records trigger, discourse insertion point, story-time interval, return point, and preserved present-state obligations.

Every element preserves source-authority refs, uses exactly one legal ownership class, and cannot modify upstream canonical values. `decision_dependencies[]` equals the projected HR1 HDD set.

## Package/result split

Ready package exact files are canonical JSON; generation session; five ordered evidence files (`dependency-assessment`, `obligation-analysis`, `option-analysis`, `projection-analysis`, `adversarial-self-review`); execution record; non-authoritative Markdown; validation; package manifest; stage completion. A single `stage-result.json` sits outside `package/`, uses `result_scope=top_level`, copies work-order sequence/timestamp, and references completion.

`required_now` produces the standard blocked package (`gate-data.json`, `blocked-report.json`, `validation.json`, `result-manifest.json`) and external blocked result, with no canonical candidate or completion. Local correction uses local-candidate revise; upstream contradiction uses blocked/upstream-defect evidence. HR1 records affected IDs and defect evidence, not final routing.

## Ready semantic conditions

- Story time and discourse order are separately reconstructable.
- No causal inversion, impossible travel, impossible communication, or state teleport occurs.
- Flashbacks, inserts, parallel tracks, and jumps have entry/return and synchronization rules.
- Pacing varies by narrative function; tension accumulates, turns, releases, and recovers without erasing core pressure.
- Knowledge and POV legality remain intact under every reorder.
- Macro density is expressed as relative bands/ranges, not invented exact word counts or scene schedules.
- The parent can consume the external result envelope without inspecting chat or hidden work.
