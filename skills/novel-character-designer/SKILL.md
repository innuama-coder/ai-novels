# novel-character-designer

## 描述

撰写小说 LLD 阶段**角色详细设计**的专用技能。输入 HLD §2（角色系统 + 弧线 + 命名）及 §10（风格与用语规范），输出每个角色的**完整设计档案**（10 节标准结构——无层级区分）。

每个进入角色设计的角色都接受完全相同的设计深度——不因"戏份多少"或"叙事权重"而缩减设计精度。

**与 HLD 的边界**：
- HLD 定义"角色是谁、有什么弧线、叫什么"
- LLD·角色设计定义"角色长什么样、怎么说话、每个场景中做什么、和其他角色是什么关系"

**方法论来源**：

本技能综合以下文献的方法论：

[1] Egri, Lajos. *The Art of Dramatic Writing*. 1946. —— 角色三维度（Physiology / Sociology / Psychology）
[2] Truby, John. *The Anatomy of Story*. Farrar, Straus and Giroux, 2007. —— 角色网络、7步设计法、鬼魂与本质
[3] Brooks, Larry. *Story Engineering*. Writer's Digest Books, 2011. —— 角色核心能力设计
[4] Weiland, K.M. *Creating Character Arcs*. PenForASword, 2016. —— 三种弧线及设计方法
[5] McKee, Robert. *Story*. HarperCollins, 1997. —— 角色维度与矛盾设计、行为一致性
[6] Maass, Donald. *Writing the Breakout Novel*. Writer's Digest Books, 2001. —— 角色深度、张力层叠
[7] Coyne, Shawn. *The Story Grid*. Black Irish Entertainment, 2015. —— 角色功能、场景内的角色价值变迁
[8] Swain, Dwight V. *Techniques of the Selling Writer*. University of Oklahoma Press, 1965. —— 动机-反应单元（MRU）
[9] Cron, Lisa. *Story Genius*. Ten Speed Press, 2016. —— 角色心理因果链
[10] Corbett, David. *The Art of Character*. Penguin Books, 2013. —— 角色声音理论（词汇/句型/沉默模式）
[11] Card, Orson Scott. *Characters & Viewpoint*. Writer's Digest Books, 1988. —— 角色类型区分与POV设计、非人角色设计方法
[12] Brody, Jessica. *Save the Cat! Writes a Novel*. Ten Speed Press, 2018. —— 角色原型应用
[13] Schmidt, Victoria Lynn. *45 Master Characters*. Writer's Digest Books, 2011. —— 原型与对立角色

## 文档格式与用语规范（9 条强制性标准）

所有角色设计文档的输出必须严格遵循以下 9 条标准。违反任意一条的文档视为不合格，需重新生成。

| # | 标准 | 规则 | 违规示例 | 合规示例 |
|---|---|---|---|---|
| 1 | **简体中文·专业正式** | 全文使用简体中文书写，语言风格为专业书面语（非口语、非随笔、非对话体、非规划性语言） | "我们首先要搞清楚角色长啥样" / "这个角色吧，还是挺复杂的" | "角色面部特征包括眉骨高度、鼻梁轮廓与下颌线走向，三者构成面部张力。" |
| 2 | **拟人化编写** | 文档读者是人类创作者（写作智能体），措辞需自然、可读，避免机器注释式表达（如 `def`/`param`/`return`/`//` 等代码注释风格） | "param: 角色姓名 / return: String" / "// 这个角色很压抑" | "角色的命名策略决定了读者在首次接触时对其产生的第一印象：全名具有权威感，代号称谓之于任务执行者则暗示其功能属性盖过个人身份。" |
| 3 | **多样化表达形式** | 根据内容需要，灵活运用 text / table / mermaid / latex 等形式呈现信息，避免单一文本段落堆砌 | 全文纯段落、无表格、无图表 | 用表格呈现角色三维度要素；用 mermaid 流程图呈现动机链路径；用 latex 表述结构关系。 |
| 4 | **书面用语·结构优** | 文档使用正式的书面表达，具有清晰的层次结构（节/子节/标号体系），禁止使用笔记体、点列式无层次的结构 | 无编号的随意列表、混用的标号层级（先用 - 后用 * 再换 1.） | 明确的 ## → ### → 标号体系。每节有标题，子节按 `§N.M` 方式编号。 |
| 5 | **最终结论·无过程** | 文档只呈现最终设计决策和结论，不包含写作过程中的思考、推测、备选方案讨论、未定事项 | "我建议把弧线设这个……但也可以考虑另一种方案……" / "可能需要再想想" | "角色弧线类型为持平弧。起点：无自我认知。终点：通过终结行为完成自我确证。" |
| 6 | **有据可循·引用完整** | 所有设计决策必须有方法论依据或 HLD 引用，不可凭空断言。参考文献必须在文档末尾完整记录 | "这个角色需要压抑一些" / "弧线就这样设计吧" | "角色在 K8 中的沉默行为基于 Swain [8] 的 MRU 理论构建——外部事件（被质问）→ 感知（问题指向异常）→ 判断（回答将触发进一步调查）→ 选择（沉默）" |
| 7 | **修订表前置** | 文档最前面必须有修订记录表，版本号须准确，每次更新必须诚实记录变更摘要 | 无修订表，或修订表内容缺失 | 见节 0 模板。版本号 v1.0/v1.1/v2.0 等，日期精确到日，变更摘要具体到修改内容。 |
| 8 | **紧扣主题** | 文档内容必须与角色设计的目的一致——不包含背景知识介绍、方法论声明（方法论在 skill 中声明）、操作说明等与"该角色的完整设计"无关的内容 | 用一段解释"为什么要用 Egri 三维度" / 引用技能说明文字 | "角色面部特征为 Egri 三维度中生理维度的核心构成要素。本设计覆盖以下 8 项体征……"（不解释 Egri 是谁）|
| 9 | **简洁清晰·禁止冗余** | 每个句子的信息密度达到最高——不重复、不解释、不铺垫。一张表格能呈现的内容不写成段落 | "首先我们来看一下弧线的设计，弧线可以分为起中终三个阶段，我们现在从起点开始看……" | 直接以表格呈现弧线三阶段，每行一个阶段，字段含阶段名/状态描述/核心认知。 |

**实现方式**：本规范作为一个独立的"格式栅格"嵌入在每个输出文档的开头（在修订表和元信息之后、正文之前，以"文档格式合规声明"的方式呈现——见节 0 模板）。写作智能体在生成文档时必须自查，在验证清单中逐条勾选。

**与验证清单的关系**：以下 9 条标准已纳入验证清单末尾。生成文档后，必须逐条确认。


## 设计管线

```
HLD §2（角色体系+弧线+命名）+ HLD §10（风格与用语规范）
  |
  +-- §1  HLD继承（参数+弧线+命名+约束——从HLD直接映射）
  +-- §2  三维度展开（Egri）——生理/社会/心理，每维度含叙事映射
  +-- §3  动机链设计（Cron+Swain MRU）——3-5条完整链
  +-- §4  语言与行为特征（Corbett+McKee）——含正式表格
  +-- §5  逐场景行为标记（Coyne）——全场景覆盖
  +-- §6  写作约束具体化（HLD §10.3逐条落地）
  +-- §7  角色关系深化（Truby）——逐对分析
  |
  +-- 输出：10节标准角色设计文档
```

## 标准文档结构（10 节固定模板）

所有角色设计文档必须遵循以下 10 节结构，不允许删减节、不允许合并节。每节的写作规格见下文。

### 节 0：修订记录 + 元信息

```
## 修订记录

| 版本 | 日期 | 作者 | 变更摘要 | 状态 |
|---|---|---|---|---|

## 元信息

| 项目 | 值 |
|---|---|
| **所属项目** | 小说「断线」·第一部 |
| **角色全名/标识** | [姓名或代号，含拼音] |
| **叙事角色类型** | [从 HLD 继承] |
| **弧线类型** | [从 HLD 继承] |
```

### 节 1：HLD 继承

包含四个子节：
- **§1.1 六参数/角色定位**：从 HLD §2 原样继承，以表格呈现
- **§1.2 弧线**：从 HLD 继承弧线的起点/中点/终点
- **§1.3 命名规则**：从 HLD §2.7 继承，含命名来源、叙事使用规则、叙事效果
- **§1.4 写作约束**：从 HLD §10.3 引用适用该角色的约束

### 节 2：三维度展开（Egri 模型）

每个维度通过**定义层 + 叙事映射层 + 叙事原则**三个层面展开。非人角色（数字生命、隐藏对抗等）需标注"适配"并说明适配方式。

| 要素 | 设计 | 叙事映射 |
|---|---|---|

**维度要求**：

| 维度 | 最低要素数 | 必须包含 | 可选扩展 |
|---|---|---|---|
| **生理** | 6+ | 身体/面容/衣着/年龄/手(或等价)/声音或感知等价物 | 角色在故事中的生理变化轨迹 |
| **社会** | 5+ | 职业/关系圈/背景/外部标签/未被他人知道的事实 | 家庭/权力位置 |
| **心理** | 6+ | 核心性格/深层恐惧/防御机制/认知盲区/核心价值观/驱动力 | 未承认的裂缝/心理结构 |

每个维度需包含**该维度对叙事的影响总结**——"这个维度如何影响读者对角色的感知"。

### 节 3：动机链设计（Cron + Swain MRU）

基于 Cron [9] 的心理因果链和 Swain [8] 的动机-反应单元，为每个角色构建 3-5 条动机链。

**标准 MRU 链结构**（适用于人类角色）：

```
外部事件 → 感知 → 判断（信念）→ 情感反应 → 身体反应 → 行动选择 → 行为
```

**非人 MRU 链适配**（适用于数字生命体等非人类角色）：

| 人类概念 | 非人等值结构 |
|---|---|
| 信念 | 已匹配模式 / 系统定义 |
| 情感反应 | 未匹配检测 + 持续处理偏差 |
| 身体反应 | 节点负载偏移 / 访问频率变化 |
| 行动选择 | 处理路径的自主决策 |

**每链条记录格式**：

```
### 链 N：[名称]

外部事件：[发生了什么]
      |
[感知→判断→反应→选择]：[逐层描述]
      |
行为：[结果]
出现场景：[场景编号/名称]
功能：[这条链在故事中的作用]
```

### 节 4：语言与行为特征（Corbett + McKee）

#### 4.1 语言特征（Corbett）

**格式**：正式角色语言特征表，必须包含以下行：

| 要素 | 设计 | 规则/约束 |
|---|---|---|
| **词汇层级** | [技术性/日常性/混合，含词汇范围描述] | |
| **句型偏好** | [短句/长句/碎片/疑问倾向/沉默倾向] | |
| **沉默模式** | [何时沉默/沉默的类型/沉默在叙事中的意义] | |
| **关键短语** | [角色高频使用的词句/或角色不用但被反复使用的词] | |
| **语气特征** | [直接/迂回/命令/请求/犹豫/不变/演化] | |

**非人角色特殊要求**：如果角色的语言在故事中*演化*（如数字生命的三阶段语言演变），必须为每个阶段独立展开语言特征表。

**极简语言角色的处理**：如果角色说话极少（如前序全书三句话），以"全部台词汇总表"替代——列出每句台词的出现时机、语境和语气状态。

#### 4.2 行为一致性（McKee）

**可信变化链**——角色的行为变化必须可追溯。格式：

| 阶段 | 场景范围 | 行为特征 | 变化触发 |
|---|---|---|---|

最少 3 个阶段。每个阶段标注触发原因（"为什么在这个时间点发生变化"）。

**行为模式记录**：

| 模式类型 | 描述 |
|---|---|
| **压力下模式** | 角色在高压下做什么 |
| **日常模式** | 角色在没有压力时做什么 |
| **关系模式** | 角色在与他人的关系中如何行动 |
| **行为标志性动作** | 1-2 个读者一看就能认出这个角色的动作 |
| **行为变化信号** | 什么细微变化表明角色的状态发生了变化 |

### 节 5：逐场景行为标记

覆盖角色出现的**全部**关键场景（含可见叙事场景 + 嵌入节点 + 背景出场）。

**格式**：

| 场景 | 该角色的行为标记 | 对比前次 | 动机链引用 | 感官/行为锚点 |
|---|---|---|---|---|

- **行为标记**：只写"做了什么、怎么做的"——不写内心独白
- **对比前次**：和上一个场景相比，这个行为"不同"在哪里——即使变化很微小
- **动机链引用**：这个行为可以从哪条动机链追溯
- **感官/行为锚点**：读者读到这个场景时"记住"的感官细节或行为细节

### 节 6：写作约束（HLD §10.3 逐条具体化）

从 HLD §10.3 中筛选适用于该角色的约束，并为每条约束提供**该角色特有的实现方式**。

**格式**：

| # | HLD 约束 | 该角色在叙事中的具体实现 |
|---|---|---|

如果 HLD §10.3 中没有直接适用于该角色的约束，基于 HLD §10 的整体风格要求为该角色派生专用约束。

### 节 7：角色关系深化（Truby 模型）

基于 Truby [2] 的角色网络理论，深化该角色与故事中**其他所有主要角色**的关系。

**每对关系格式**：

```
### §7.N [角色A] ↔ [角色B]

| 互动维度 | 定义 |
|---|---|
| **权力结构** | [谁在关系中处于什么位置] |
| **情感距离** | [从远到近/从近到远的演变] |
| **沟通模式** | [如何交流/交流什么/不交流什么] |
| **未言明的张力** | [双方没说出来的东西] |
```

最少覆盖 3 对关系。关系分析必须包含"故事进程中关系的变化"——不是静态描述，是演变的。

### 节 8：参考文献

列出本文档引用的方法论文献 + HLD 具体节号。格式：

```
[1] [作者]. *[书名]*. [出版商], [年份]. —— [应用说明]
[2] HLD「断线」§[节号] [内容描述]
```

## 特殊角色类型的适配说明

### 非人角色（数字生命体、群体角色等）

标准 10 节结构对所有角色类型生效，但各节的展开方式需根据角色类型进行**定义层适配**：

| Egri 维度 | 人类角色 | 数字生命体（适配示例） | 群体角色（适配示例） |
|---|---|---|---|
| **生理** | 身体/面容/衣着 | 计算架构层（节点阵列/感官通道/"面容"如呼吸灯/"手"如通讯窗口文字）| 群体的构成模式/共性行为特征/个体差异的省略策略 |
| **社会** | 职业/关系圈 | 数据生态层（访问层级/交互协议/生态位）| 群体在组织中的功能位置/与主角的交互模式 |
| **心理** | 性格/恐惧/盲区 | 涌现系统层（处理偏差/未匹配检测/认知盲点为"认为所有模式都是先存的"）| 不适用于群体的心理分析——替换为"集体的行为逻辑" |

**适配原则**：
1. 每一层适配必须有明确的"人类概念 → 角色等价结构"的映射说明——不能让读者猜测
2. 适配不能省略叙事映射——每个适配维度都必须说明"读者如何感知到这个存在"
3. 如果角色类型需要独创的维度结构（如出卖者的"缺席型设计"），必须在三维度展开前标注"适配声明"

### 隐藏/缺席型角色（出卖者）

标准三维度（生理/社会/心理）在缺席型角色中替换为：

| 替换维度 | 原维度等价 | 定义 | 必须包含 |
|---|---|---|---|
| **数据痕迹层** | 生理 | 角色在故事世界中留下的唯一物理证据 | 数据点的精度级别/信息来源/叙事中如何呈现给读者 |
| **叙事功能层** | 社会 | 该角色的缺席如何影响其他角色的行为 | 每对关系的作用方向/信息不对称的类型/叙事效果 |
| **缺席存在层** | 心理 | 角色因"不被揭示"而产生的张力 | 不可知内容及其设计理由/第二部的留白空间 |

适配声明必须出现在节 2 开头：

```
*本角色为缺席型设计——标准 Egri 三维度无法直接应用，以下使用适配结构。*
```

## 验证清单

```
[ ] 文档包含全部 10 节（修订记录+元信息 / HLD继承 / 三维度 / 动机链 / 语言行为 / 逐场景标记 / 写作约束具体化 / 角色关系深化 / 参考文献）
[ ] 无"精简版""轻量版"或任何层级区分——所有角色同等深度
[ ] 三维度每维度至少 5-6 个要素，含叙事映射
[ ] 动机链 3-5 条，每条含完整（事件→感知→判断→反应→选择→行为）结构
[ ] 动机链标注了"出现场景"和"功能"
[ ] 语言特征表包含全部 5 个要素（词汇/句型/沉默/关键短语/语气）
[ ] 非人角色有适配声明和三阶段或等价的分阶段语言展开
[ ] 行为一致性含最少 3 阶段可信变化链
[ ] 逐场景标记覆盖该角色出现的全部关键场景

[ ] 写作约束从 HLD §10.3 逐条具体化——不空转、不照搬

[ ] 参考文献完整（方法论 + HLD 节号）
[ ] 无"我觉得/可能/或许"——所有设计以陈述句书写
[ ] 角色类型特殊时（非人/缺席/群体），在节 2 开头标注适配声明

[ ] 全文使用简体中文专业书面语——禁止口语/随笔/代码注释风格
[ ] 文档拟人化——读者是创作者，不是机器
[ ] 至少使用一种非文本表达形式（表格/图表/Mermaid/Latex 等）——禁止纯段落堆砌
[ ] 层次结构清晰——## → ### → §N.M 体系完整
[ ] 无过程性内容——所有语句均为最终结论，无"可能/或许/建议"
[ ] 所有设计决策有引用依据——参考文献完整
[ ] 修订表已填写——版本号/日期/变更摘要/状态
[ ] 内容紧扣角色设计目的——无方法论声明/背景介绍/技能引用
[ ] 无冗余——每个句子的信息密度最高，无重复无铺垫
[ ] 文档专用——如果角色类型特殊（非人/缺席），在节 2 开头标注适配声明
```
