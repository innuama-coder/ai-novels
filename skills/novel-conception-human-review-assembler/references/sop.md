# 小说构思人审报告 SOP

> Legacy 1.x only. 以下 R1/D1 命令和字段仅供旧包维护。V2 执行必须遵循
> [review-plan-contract.md](review-plan-contract.md) 和 `scripts/run_v2.py`，
> 不得回读或迁移旧输入。

## A. 设计阶段

1. 确认当前工作发生在 R1 技术 `ready` 之后、作者最终批准之前。
2. 运行 `prepare_source_inventory.py`。若失败，停止并返回 R1。
3. 阅读 R1 `novel-design-brief.md` 获取人类语言概览；所有事实回到 D1 `map-data.json` 与 R1 审核对象核验。
4. 先写 `review_contract` 与 `reading_budget`，再设计内容。`work_title` 必须来自
   输入中的作品标题，不得从梗概、run id 或目录名猜测。不要先长篇总结后强行删减。
5. 设计快速定向，并先建立六层控制总链：
   `世界观命题 → 世界规则 → 事件环境 → 故事架构 → 人物选择 → 终局契约`。
   每层必须回答“为何推出下一层、控制什么、必须成立什么、禁止怎样解释”。
6. 设计世界运行图：
   - 每个系统说明规则、权限、资源、代价或失败；
   - 每个主要环境说明特征、要素、进入/危险、故事功能和变化；
   - 把硬边界与开放接口分开。
   - 为每个系统和环境写一句可独立审阅的控制摘要，禁止只留名词标签；
   - 逐环境列出其承载的主要事件，证明环境是事件容器而非装饰。
7. 设计多线时间线与事件控制链：
   - 保留全部 D1 故事线；
   - 将开发单元压缩为 3–8 个评审阶段；
   - 每阶段写清压力、选择、后果/代价和新状态；
   - 建立 unit 到阶段的完整映射。
   - 逐一覆盖全部 major event，明确前提、决定性变化、结果、所属线、环境、
     参与人物及它锁定的后续事实。
8. 设计人物与关系图：
   - 覆盖全部评审相关人物；
   - 先写责任、权限、不可委托选择和禁止解释，再写目标与弧线；
   - 至少保留三个关系层级；每段关系写明触发、变化、控制对象与必须成立项。
9. 设计 2–4 个片段 slot。每个只验证一组明确问题，合计覆盖六类体验目标。
   同时检查必含专名和术语所用文字系统，为 CJK 与拉丁文本分别保留可用长度。
10. 写四个作者判断问题和八项理解任务。
11. 建立 `coverage_ledger`。逐项处理 source inventory，并确认目标可见元素自身
    实际引用该来源；不凭印象或账本自声明完整。
12. 运行 `export_fragment_briefs.py`、`write_execution_record.py` 与 plan 验证。

## B. 失败处理

- 上游 hash、status 或 validation 失败：返回 R1，不生成摘要。
- 世界、故事、人物对象遗漏：修订 plan 与覆盖账本。
- 超过十分钟：保留控制摘要与主要事件链，减少重复解释，将支持性运行参数放入
  可展开追溯层，或缩短片段预算；不得删除决定所需的因果或边界。
- 无法在预算内表达：报告 `blocked`，说明构思规模需要分卷/分册评审，而不是静默延长。
- 片段需要 D1 未授权事实才能成立：返回 D1/R1，不在 brief 中发明。

## C. 片段交接

只交付 `fragment-briefs.json`。后续片段技能必须：

1. 逐 slot 写作，不自行改变评审问题；
2. 遵守必含、禁写、POV、信息控制和长度；
3. 将局部创作选择列为 `creative_choices`；
4. 不产生新的权威事实；
5. 自己完成文学与契约验收后再返回片段包。

本技能不得替片段技能“先写一版”。

## D. 组装阶段

1. 重新验证 plan 与 R1 当前状态。
2. 调用片段技能的 canonical validator，验证三阶段写作证据、当前技能绑定、
   manifest、plan hash、ID 集合、brief compliance、长度与来源。
3. 运行 `assemble_human_review.py`。该脚本只做合并、计数、渲染和 manifest。
4. 运行 assemble 验证。
5. 把 `human-review-report.json` 交给后续 HTML 技能；Markdown 只用于内容核验。

## E. HTML 交接边界

HTML 技能可以：

- 选择布局、颜色、图形表现和交互；
- 做不隐藏关键事实的渐进披露；
- 对照可访问性要求实现标题、键盘和替代文本。

HTML 技能不可以：

- 改写、删减或重排本报告的权威内容；
- 把必须信息移入默认不可见区域；
- 重新解释片段；
- 代替作者写入批准结论。
