# 小说构思人审内容设计与组装

## 目标

让不参与生产流程的人在十分钟内理解并判断：

1. 这是一部什么小说。
2. 世界是否能承载故事。
3. 故事是否完整、有起伏且因果成立。
4. 人物是否会以可信方式作出关键选择。
5. 样章呈现的阅读体验是否符合预期。

## 输入

规划阶段只接收当前 validator-ready P1、H1 input gate、作品名和 initialized workspace。

组装阶段只接收同一 run/session 的正式 H1-A plan、H1-B fragment package、对应 workspace 与 active return（如有）。始终先运行正式 validator，不接受手工摘要代替正式包。

完整运行与 lineage 约束见 [runtime-contract.md](references/runtime-contract.md)。

## 内容顺序

严格按以下顺序组织：

1. 世界设定
2. 故事线设计
3. 角色定义
4. 样章
5. 评审结论操作

第五项只是操作区，不是第五个内容维度。

## 人类呈现硬契约

- 第一屏先回答“这是一部什么小说”，不要先解释评审方法。
- 世界设定必须回答“这个故事世界是什么样，与故事相关的关键信息是什么”，并合并
  呈现世界背景、时代与现实关系、国家／组织关系、核心任务活动、运行规则和具体环境；
  不得把世界板块缩减为主题或规则摘要。
- 每个上游主要环境必须获得独立的人审条目，说明空间位置与用途、可感知特征和关键
  物件、允许行为、限制／风险及其承载的故事活动。禁止把多个环境压成“证据／任务”
  一类目录标签。
- 每个环境定义的第一句必须是可独立阅读的环境概要；十分钟默认阅读面显示该概要，
  空间、物件、权限和风险等完整定义可在同一条目内展开阅读，不得移入机器审计文件。
- 世界环境图必须逐一覆盖全部主要环境并显示实际连接或流转关系；不能用无连接的分类
  词组代替空间与活动关系。
- 每个模块保留面向人的标题。
- 每个模块正文只公开标题和结论；对故事的影响与模块级边界保留在机器模型中，只有经过归并的关键边界进入对应板块末尾。
- 使用自然、具体、可直接理解的简体中文。
- 故事线应像讲故事一样说明起点、变化、连接、高潮与结局。
- 多线故事必须以共享时间主轴作为主要呈现：横轴是共同阶段，纵轴是并行故事线；完整标出埋点、探针、转折、高潮、回收与余波，并显示各线交汇点。故事线架构图只能补充，不能替代时间主轴。
- 每个 C1 角色必须有一个独立的人审条目，先用一句话说明故事位置，再完整定义其参与活动、外貌辨识、性格机制、生活背景、职业与日常、社交圈和具身/接口边界。
- 关系图负责说明人如何相互改变，不能代替逐人的个体定义；群体职责摘要也不能代替独立角色条目。
- 环境必须说明事件能在那里做什么、不能做什么以及失败代价。
- 样章正文不得夹带用途说明、来源绑定或生成解释。
- 禁止把箭头速记、拓扑计数、阶段 ID、来源锚点、哈希或 JSON Pointer 当作正文。
- 不得为了十分钟预算把完整结论压缩成 Agent 备忘录。

`validate_review_plan()` 必须拒绝机器速记或审计术语进入公开文案。完整 P1 覆盖仍由 reduction ledger、drilldown index、presentation bindings 和 source coverage 在机器文件中验证。

## 规划阶段

依次完成：

1. `review-task-analysis`
2. `information-architecture`
3. `visual-and-fragment-plan`
4. `ten-minute-budget-test`
5. `final-review-plan`

必须使用 `scripts/run_v2.py` 的 `run_plan()`；每阶段只提交一次。计划必须覆盖五个固定语义图：控制逻辑、世界环境、故事线架构、主要事件时间线、人物关系。

阅读预算计算只约束人类实际可见内容。来源 ID、图形逐值数据和审计证据不计入正文，也不得通过折叠区公开。

## 组装阶段

使用 `run_assemble()`：

- 保留 plan 中的模块标题、自然语言结论和边界。
- 严格投影已经验收的样章，不重写样章。
- 生成 `human-review-report.json`、`human-review-report.md`、执行记录、validation 和 manifest。
- 机器追溯字段保留在 JSON 中供后续验证，HTML 技能决定哪些字段可公开。
- 先由独立任务调用 `novel-conception-presentation-fidelity-reviewer` 审查候选
  report；把其 `presentation-fidelity-review.json` 作为必填输入交给
  `run_assemble()`。规划者或样章写作者不得兼任审查者。

## 边界

- 不修改 P1、H1 plan、fragment package 或上游 workspace。
- 不新增小说事实，不替作者作出批准、修改或否决决定。
- 不生成 HTML、CSS、JavaScript 或 H1 completion。
- 不把来源一致性证明误当成人类正文。

## 验收

只有以下条件同时成立才可交付：

- 正式 plan/assembly validator 均为 ready。
- 四个内容维度顺序正确，评审操作位于末尾。
- 所有公开模块均有人类标题和自然语言结论。
- 十分钟预算只计算实际可见内容且不超过 600 秒。
- P1 来源覆盖完整，公开内容与来源绑定一致。
- 独立呈现一致性审查逐元素覆盖且 `verdict=pass`；缺失、同任务复用、内容
  hash 漂移、证据非候选原文、关键遗漏、矛盾或权威升级均阻断发布。
- W1 世界前提与组织、E1 核心活动和每个主要环境均进入世界板块；每个环境单独投影，
  环境图逐一覆盖且连接闭合。
- C1 每个规范角色均且仅均有一个独立公开条目；条目绑定同一个角色来源并包含故事位置、活动参与与六项个体画像。完整定义原位展开，一句话概要进入十分钟默认阅读面。
- 样章数量、顺序、文字与 H1-B 完全一致。
