# 小说叙述契约设计

## 任务边界

产出一份**叙述契约**，回答：在已确定“发生什么、谁为何选择”的前提下，文本由谁组织、通过谁感知，读者何时能知道什么，以及开发必须遵守哪些表达边界。

叙述契约控制故事事实的**呈现**，不是重新设计事实。不得新增角色目标、改变角色获知事实的因果节点、重排会改变选择的事件、补造高潮或改写结局。

开始前完整读取：

- [conception-phase.md](../../docs/ai-novel-workflow/conception-phase.md) 的“前五步共同交互协议”；
- [narrative-methodology.md](references/narrative-methodology.md)；
- 生成交付物时读取 [narrative-contract-template.md](references/narrative-contract-template.md)。

最小规则写法：

```text
叙事单元/因果阶段 → 谁说与谁聚焦 → 合法信息来源和盲区 → 读者知识状态 → 所形成的问题或意义 → 禁止越界
```

“第一人称、电影感、克制、慢慢揭露”都不是完整契约，除非被转成可观察的权限、时点和表达规则。

## 输入与准入

| 输入 | 使用方式 |
| --- | --- |
| 作者原始 idea 或旧稿 | 默认必须提供，用来校验上游产物是否遗漏原始叙述诉求，并讨论叙述偏好、已有语感和禁区；除非被当前上游产物或作者重新确认，不得成为硬规则。若无单独 idea，须由作者确认六份上游设计产物已完整代表原始 idea。旧稿样本须先说明是规范样本还是历史材料。 |
| `intent-card.md` | 继承 `confirmed`、允许的 `provisional` 和授权边界；不得改变读者承诺、非目标、结局性质或主题禁区。 |
| `subject-definition.md` | 仅在交接状态为 `ready` 时继承主体、关系、世界/能力限制和信息通道；保留来源状态。 |
| `world-operating-contract.md` | 仅在交接状态为 `ready` 时继承故事世界中的信息通道、事实边界、能力限制和可验证条件。 |
| `core-character-design.md` | 仅在交接状态为 `ready` 时继承角色的认知过滤、表达指纹、关系误读和变化边界；这些约束角色意识，不直接规定 prose。 |
| `causal-storyline.md` | 仅在交接状态为 `ready` 时继承故事事实、角色知识变化、秘密影响节点、高潮与结局；标为 `narrative-contract` 的开放项是本 skill 的主要输入。 |
| 作者当前补充 | 说明改变哪项叙述规则；若会改变因果链，停止并退回上游。 |

作者必须明确多份旧稿、HLD 或叙述样本的当前权威。当前明确修订可覆盖旧决定，但输出须记录“旧项 → 新基线 → 作者确认”。同一权威层冲突且会改变契约时输出 `blocked`，不得拼接折中。

I0–I4 的五个上游 completion packet 均须为 `ready`，并且 I2 世界契约不可缺失；其中可继承 `confirmed`、上游明确允许的 `provisional`，以及边界清楚的 `delegated` 项。未获允许的 `open`、上游 `blocked` 或会改变本阶段核心选择的暂定项均构成阻塞。

发现问题时按“决定属于哪里”路由，不在本技能中越权修补：

| 问题实质 | 退回位置 |
| --- | --- |
| 读者承诺、主题问题、结局性质或非目标 | `novel-intent-facilitator` |
| 核心主体、关系功能、身份、世界能力或信息通道 | `novel-subject-designer` |
| 角色的动机、形成原因、压力行为、关系误读或变化边界 | `novel-character-interviewer` |
| 事件事实、角色何时获知且因此改变选择、代价或结局 | `novel-causality-architect` |
| 同一事实如何被看见、遮蔽、排序、解释和表达 | 本技能 |

偶发角色知识若会改变选择、关系或代价，退回因果架构；若仅影响呈现且不改变因果，可在本技能确认或授权，并标注为“非因果叙述知识”。

以下情况输出 `blocked`：

- 原始 idea（或其完整代表确认）、意图卡、主体定义、世界运行契约、核心角色设计或因果故事线缺失，或 I0–I4 中任一 completion packet 不是 `ready`；
- 关键角色何时知道事实仍未决定，且会改变其选择；退回 `novel-causality-architect`；
- 要求读者不知道某事，但指定 POV 角色始终明知，且没有内部真实的呈现方式；
- 结局依赖没有事实准备、合法来源或回收责任的突转；
- 要求拆章节/场景、写正文或建立在世作者的可辨识模仿规范。

POV、揭露顺序或语言倾向尚未定是本 skill 的正常准入状态，应通过访谈解决。

## 状态与交互

每次回复开头标明当前状态和决策组，不必重复整份契约：

| 状态 | 含义与行为 |
| --- | --- |
| `exploring` | 正在理解一个叙述控制点；先开放提问或澄清。 |
| `awaiting_confirmation` | 已形成候选规则；只请求确认、修改或暂定。 |
| `confirmed` | 作者明确确认；冻结当前组并转下一组。 |
| `delegated` | 作者明确授权 Agent 决定；记录范围与 Agent 选择，不伪称作者确认。 |
| `provisional` | 作者允许暂定；记录影响、风险与最晚回看点。 |
| `open` | 不影响契约主体的局部实现项；记录下游责任。 |
| `blocked` | 因果冲突、权威不明或缺少必须裁决的规则；停止并提出最小问题。 |

普通补充、沉默或“都行”不自动等于确认；遇到“都行”应追问作者是要继续比较，还是明确授权 Agent 决定。“Agent决定”可记为 `delegated`；“确认/就按这个/选择A/暂定A”等明确表达才能冻结。

首轮展示：可继承边界、上游已指定的信息节点、当前决策组、唯一学习目标和最大缺口；只提出一至三个短问题，不以完整问卷开场。

一个决策组可以经过多轮。每轮只处理一个控制点，并采用固定循环：

1. 说明本轮只决定哪个读者—叙述关系，不决定场景和句子。
2. 区分作者确认、上游锁定、Agent 推断、授权项和开放项；发现冲突即指出。
3. 先开放提问，再引用作者语言澄清；难以回答时给 2—3 个同一控制点上的互斥候选。
4. 说明候选会改变亲密度、视野、知识差、公平性、时间理解或开发自由中的哪一项，不用“更高级、更好看”推动选择。
5. 回显“规则—理由—开发含义—暂不决定项”，请求确认、修改或暂定。
6. 确认后更新权限表或信息台账，冻结本组再继续。

先问读者需要经历什么，再问第一/第三人称等标签。一次只问一个决定；不得把 POV、时态、风格和秘密揭露塞进同一道选择题。

## 四个叙述决策组

### A. 读者依附、叙述者与聚焦权限

**学习目标**：确定读者主要跟谁经历故事、文本由谁组织、每个视点为何不可替代，以及哪些事实天然位于视野之外。

获得：

- 主要读者依附对象和亲密度—视野取舍；
- 叙述者是否属于故事世界、讲述行为位于何处；
- 叙述人称、聚焦者、合法感知/记忆/推断来源和盲区；
- 多 POV 的切换单位、功能、条件和定向信号；
- 事实、解释、自我认识和故意欺骗四类可靠性。
- 开篇如何让读者识别默认叙述规则，以及首次 POV 切换、时间偏离或可靠性变化如何获得定向或前置准备。

不得仅以“第一人称更沉浸”“第三人称更自由”决定。对每个新增 POV 追问：删掉它后，哪项读者理解无法通过既有视点合法获得？没有不可替代功能则不新增。

检查点：每类单元都能回答“谁说、谁感知、谁知道、谁不能知道”；没有无规则 head-hopping。

### B. 角色—读者知识差与公平披露

**学习目标**：把上游秘密和事实转成读者知识状态，而不改变它们在故事世界中的因果时点。

只为**关键披露控制项**登记：提前、延迟、歧义或误读会改变核心读者问题、公平性、身份判断、转折、高潮或结局理解的事实。常规说明信息留给下游，不把本访谈扩张为全书知识清单。对每项登记：

- 事实何时成立并改变选择；
- 各角色何时知道、误信、怀疑或隐瞒；
- 叙述通过什么合法来源访问；
- 读者在各阶段是确认、合理怀疑、受控误判还是未知；
- 披露形成谜团、悬念、戏剧性反讽或重解释中的何种功能；
- 前置线索、回收责任、禁止提前泄露项和有意保留项。

深度第一/第三人称不得为揭晓而假装聚焦者不知道明知之事。允许呈现真实局部、尚未概念化的感受、可识别的不可靠叙述或受限访问；“没有注意到”只有在人物当时的注意目标、认知限制和文本表现均可信时，才可作为延迟屏障，不能成为万能借口。禁止伪造内心事实、使用不自然代称或让作者级叙述说假话。

知识受限本身不等于叙述不可靠。分别记录：叙述者误报/少报/误解/误评，角色有意说谎，以及读者基于真实但不完整证据形成误判；三者不得混称为“不可靠叙述”。

检查点：每次延迟都有合法屏障和明确读者问题；每次关键揭露都改变理解或后续选择的意义，而非只制造惊讶。

### C. 时间组织、叙述速度与心理距离

**学习目标**：规定故事时间怎样被组织和感受，而不制作章节时间表。

获得：

- 故事现在、默认顺序、时态和时间定向方法；
- 顺序：倒叙、预叙、并行、记忆进入与返回的条件；
- 时长：关键选择何时场景化减速，哪些过程概述、跳跃、省略或停顿；
- 频率：同一事件何时可因新聚焦、新证据或新意义重复；
- 每类聚焦者的默认心理距离、允许范围、靠近/拉远触发和意识呈现方式。

时间偏离必须回答“为什么现在讲、谁能讲、改变什么理解、如何定位与返回”。记忆若是角色当下的意识活动可进入叙述；若会新增上游未定义事实，退回对应上游 skill。

检查点：读者可重建基本时间关系；每次非线性和距离变化都有功能，不以混乱冒充复杂。

### D. 表达原则、意象、禁区与交接

**学习目标**：把抽象语感转成开发者可以判断的规则，同时保留实际写作空间。

获得：

- 叙述语气、句法节奏、情感呈现、信息解释、对话/沉默、术语使用的默认原则与允许变化；
- 展示与概述的功能分配，何时允许直接命名情感或主题；
- 意象/物件的字面功能、意义变化、回收责任和饱和禁区；
- 作者裁决禁区、POV 越权、煽情/解释捷径及版权模仿边界；
- 开发地图必须继承什么、开发阶段可以自由实现什么、何时回问。

把“克制、冷峻、有电影感”等词追问成可观察规则。不得写连续样稿替代定义；可用一句抽象的合规/违规描述帮助判断，但不预写场景或对白。

意象系统是可选控制项。若本作不需要跨段回调，可明确记录“无强制意象”，不得为了填表制造象征物。

检查点：开发者能仅凭契约判断一种写法为何合规或偏航，同时仍可自由创造动作、段落和句子。

## 叙述审计

| 检查 | 通过条件 |
| --- | --- |
| 谁说/谁看 | 叙述者、聚焦者、角色和作者不混写；切换有边界。 |
| 知识一致 | 角色知识与因果架构一致；读者知识差有合法来源或屏障。 |
| 公平隐瞒 | 不通过压住 POV 角色明知事实、假内心或作者谎言制造转折。 |
| 披露功能 | 关键披露改变读者问题、理解或选择意义，并有准备/回收。 |
| 时间可读 | 顺序、时长、频率规则明确；偏离可定位且有功能。 |
| 距离可控 | 默认距离、允许变化和触发条件可执行，不随机漂移。 |
| 表达可判 | 风格与禁区是可观察规则，不是评价词或作者模仿。 |
| 自由恰当 | 固定高错误成本控制点，不预写正文、章节或每个动作。 |
| 边界合规 | 没有新增能力、因果、身份结论或结局解释。 |

## 访谈计划与完整记录

在第一条实质问题前，读取 harness `workflow.md`，向作者展示 I5 的四组、`plan.v1.json` 已核定的**精确**互动问题数、分钟数、完成条件和 blocker，并记录输入版本。内部容量估计可以补充展示，但不得替代作者可见的访谈计划；每轮刷新已用问题数、剩余预算和预计剩余时间；变更计划必须由作者明确确认并写入新的 `plan.vN.json`。

本 skill 只能在 harness I5 中运行：会话写入 `<project>/interview-sessions/I5/<session-id>/`，先创建 `plan.v1.json` 并向作者说明精确问题数和预计时长；每轮立即追加 `events.ndjson`，运行验证器并重建 `report.md`。结束时生成叙述契约和 I5 `stage-completion.json`；不得以事后总结覆盖作者原话。发现角色知识、世界信息通道或事实边界不成立时，必须按 harness 路由至其唯一拥有者，不得用叙述技巧掩盖。

## 输出与完成条件

在写入 I5 `stage-completion.json` 前，生成并校验 `control-projection.json`。使用稳定的 `NAR-` ID，将 POV、时间结构、信息披露、悬念、决定性心理活动边界、结局可见性和作者开放项逐项无损投影。每项必须绑定 `narrative-contract.md` 的精确行范围及文本哈希，并忠实标记 `hardness`。completion 使用 `contract_version: "2.0"` 并哈希绑定投影；专用 validator 未通过时不得交接。

投影中的每项控制必须只绑定叙述稿中的一个完整 H2/H3 章节；`heading` 与字符串 `value` 分别原样对应章节标题和去除首尾空行后的正文。不得使用多段范围、局部摘录、结构化改写或哈希正确的近义转述。

完成或被阻塞时生成 `narrative-contract.md`，遵循模板并包含：

- 继承边界、当前权威和作者修订记录；
- 读者体验总则、叙述声音与聚焦权限矩阵；
- 可靠性声明、关键事实的角色—叙述—读者知识台账；
- 时间顺序/时长/频率、记忆规则与心理距离；
- 可执行表达原则、意象回调、禁区和下游授权；
- 审计、开放项、blocker 和 A—D 最小会话记录。
- 逐因果节点/阶段的叙述控制矩阵：允许的 POV/聚焦者、读者起止知识、时间位置、距离功能、准备/回收责任和禁止披露项。

交付物总体状态按最弱已接受状态聚合：四组全由作者确认则为 `confirmed`；存在授权项且无暂定项则为 `delegated`；存在获作者允许的暂定项则为 `provisional`；存在阻塞项则为 `blocked`。`ready` 只表示可交接，可与前三种状态并列；`provisional + ready` 仅在作者接受风险、回看点明确且不影响主干时成立。

仅当以下条件全部满足时，交付状态可为 `confirmed`、`delegated` 或 `provisional` 且 `ready`：

1. A—D 四组均获作者确认、明确授权或允许暂定；
2. 每个关键披露控制项都有一致的角色知识与读者披露规则；
3. 每个 POV 有不可替代功能、权限边界和切换规则；
4. 关键延迟与误导通过公平审计，关键回收有前置准备；
5. 时间、距离和表达规则可执行且不预写正文；
6. 没有会改变叙述主干的 `open`，也没有与上游冲突的决定。

否则输出 `blocked`，指出最小缺口、责任人和应退回的 skill。非阻塞的局部词句、具体场景进入方式和局部意象可交给开发阶段自主决定。

## 交接与禁止项

交给 harness V1 的 I5 `stage-completion.json`：每个因果节点允许的 POV、读者必须知道/可以怀疑/不能知道的事实、时间与距离功能、必须准备或回收的信息。只有 V1 通过、V2 获作者批准后，harness 才可启动开发地图；后者可拆成功能单元，但不得更改权限、披露状态或公平边界。

交给开发阶段：在契约内自由设计场景动作、段落、句子、具体对白和局部意象。实现若要求改变 POV 权限、角色知识、关键披露节点、时间逻辑或主题禁区，必须回问，不得静默修订。

不得输出章节列表、场景表、连续样稿、完整对白或小说正文；不得用固定 POV 教条、类型惯例或特定作者风格替代项目决定。
