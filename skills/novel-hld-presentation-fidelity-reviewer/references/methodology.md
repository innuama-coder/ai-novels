# Methodology

## Independent evidence posture

Separate producer and reviewer task identities. Freeze the compared bytes and actual read set in `review-session.json`. Treat prior assembler reasoning as irrelevant: only HP1, the report, and their declared bindings are evidence.

## Bidirectional traceability

Review forward from every report element to HP1 to catch fabrication, enhancement, misattribution, and wrong values. Review backward from every material HP1 control to the report to catch omission and weakening. A source link alone is insufficient; the displayed meaning and authority strength must match.

## Semantic equivalence, not wording identity

Compare fact, relation, order, state, scope, modality, attribution, and open/closed status. Allow plain-language paraphrase when these remain invariant. Treat “must”→“may”, “open”→“decided”, changed agent/subject, reversed direction, or narrowed scope as material drift.

## Visual-data fidelity

Reconstruct every visual model as nodes, edges, ordering, categories, values, source sets, and textual alternative. Compare these sets and directions to HP1 and the adjacent report conclusion. Flag omitted context, reversed relations, inconsistent scales/categories, or visual emphasis that implies a stronger conclusion. HH1-B judges semantic data, not rendering aesthetics.

## Decision retrieval testing

Simulate an author who sees only the report. Answer ten frozen questions—including the macro world-environment, character-definition, and concrete-place-definition questions—and cite the exact HRE/HVG/source/locator path. A plausible answer from reviewer memory does not pass. Retrieval fails when the answer is missing, ambiguous, distributed beyond the budget, or requires upstream material.

## Cognitive overload and accessibility boundary

Check whether conclusion discovery is obstructed by repetition, process noise, jargon, redundant visuals, or buried controls. Verify that visual data have an equivalent textual conclusion/alternative, but do not inspect HTML, contrast, keyboard behavior, or DOM semantics; HH1-C owns those implementation checks.

## Materiality and verdict

Findings are material only when they could change an author's understanding, approval, revision target, or LLD boundary. Style preference alone is not drift. One material drift or failed fixed retrieval task prevents pass. Reviewer execution defects produce revise, never a false upstream failure.
