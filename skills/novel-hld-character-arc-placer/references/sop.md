# HC1 SOP

## 1. Admit current structure and lines

Verify HC1 identity, ordered `[HB0, HA1, HS1]` completions, current hashes,
allowlist, and return binding. Resolve stable IDs through registered roles.

## 2. Assess unresolved dependencies

Create one `HDD-HC1-<source_id>` per projected source before any candidate.
Stop for external author resolution when disposition is `required_now`.

## 3. Freeze authority

For every core/important character and relationship, record authoritative
goals, values/beliefs, responsibilities, feelings, capabilities, permissions,
knowledge, beginning state, ending control, and open items. Mark absent facts as
out of scope; do not fill them.

## 4. Map participation

Walk each HS1 segment and connection. Assign an authorized responsibility or a
specific legitimate absence to each relevant character. Identify all key
results requiring an actor.

## 5. Generate arc-placement options

Compare at least two materially different legal placements, or document why
only one preserves event and relationship authority. Test agency, pressure,
choice, cost, consequence, line function, and downstream information needs.

## 6. Project arcs and relationships

Create state models; start, pressure, choice, cost, and result steps; bilateral
relationship steps; choice-cost-consequence links; event alignment; and
capability/information/permission checks. Bind each to existing IDs.

## 7. Adversarial review

Attack every change as a possible jump, author invention, plot compulsion,
unsupported action, one-sided relationship, or unowned result. Cite actual IDs
for every pass conclusion.

## 8. Publish

Run the deterministic entrypoint. Only its package and external result envelope
are consumable; Markdown and conversation are never canonical.
