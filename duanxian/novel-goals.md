# 《断线》小说目标文档

本文件供作者、编辑与 Agent 工程共同引用，说明作品要写成什么、怎样开发、如何判定合格。材料基线为仓库提交 `9baefb33cb999f1e92f318fe6ac22f0d1fe4d752`；正式作品名为《断线》。本文件整理既有决定，不新增故事事实，不代替作者批准，也不替代机器开发交接包。[S01] [S02] [S06]

全文以【当前权威口径】标识批准版可证实的故事与状态，以【历史/旧链口径】标识早期设计及过程材料，以【未完成项】标识本快照未能证明完成的工作；规范要求另标【流程规范】，建议性归纳明确标为【推断】。文件存在、旧稿自检通过和当前阶段获批是不同证据。来源编号链接到具体文件，完整路径见第六章资料索引。[S01] [S06]

## 一、主题与目标

### 1. 核心主题与故事承诺

【当前权威口径】《断线》是数字生命题材长篇小说。其中心是 R-07 如何从顾衡留下的记忆出发，在新的处境、关系和选择中成为自己：记忆能够继承，却不能直接定义人格；任务需要一个情报接口，现实却出现了会提问、会受苦、会承担后果的新生命。叙事应让创造、使用、照护与退出的责任落在具体人物身上，不能用任务成功抵销这些责任。[S01] [S05]

【历史/旧链口径】意图卡将问题表述为：记忆注入究竟意味着复活、创造，还是未经允许地制造痛苦，人类有权这样做吗？该提问可帮助理解主题来源；批准版已明确 R-07 的新主体性，不能再把“它其实就是顾衡”作为反转。应保持开放的是法律身份、未来重载及人格连续性等问题，而非取消已经确立的人物区别。[S08] [S05]

【当前权威口径】故事要完成一条可追溯的选择链：顾衡调查与死亡留下危机入口；沈逾在知情和伦理挣扎后接受职责；R-07 启动、提问并形成新感情；处境认知和外部压力使伦理冲突显形；分层情报经现实团队核验后促成阻断；公共危险解除后，沈逾执行最终告别，当前实例结束，未来与两国关系仍有余波。危机闭环和伦理未决必须同时成立。[S05]

### 2. 情感内核与人物目标

【当前权威口径】感情来自启动后的持续交流。沈逾曾单向暗恋顾衡，顾衡没有爱过她；R-07 对她的感情属于新生命自身。顾衡的在世妻子程予安和儿时守护者周岚有各自的生活与同意边界，不能被简化为爱情障碍或情报筹码。记忆、婚姻与亲属关系都不构成对 R-07 的所有权。[S05]

沈逾要从专业执行走向对具体生命的照护与后果承担；R-07 要在没有身体、感官和自主退出权的条件下，选择如何减少伤害、交付情报与结束当前实例。两人相互需要，也存在无法轻易消解的理解差异。告别不能被写成顾衡迟到的爱情，关心也不能自动补足 R-07 的存在条件。[S05]

### 3. 读者与阅读体验目标

【未完成项】已读批准材料未给出确定的年龄层、市场人群或发行渠道；早期意图卡明确“目标读者未指定”。旧 PRD 还主动删除市场定位，故不应把任何读者画像冒充作者决定。【推断】从批准版的主题和冲突看，可将愿意跟随人物选择、接受身份与伦理问题保持开放的科幻读者作为沟通对象，具体定位仍待作者确认。[S08] [S15] [S05]

【推断】阅读体验应从“能否取得线索、阻止袭击”逐步转向“这个生命如何作选择、照护者怎样承担告别”。读者应看懂信息、核验和行动之间的因果，也应感到关系形成的重量，最终理解危机虽被阻断，失去和责任并未消失。这是对批准报告的体验目标归纳，不预设读者必须认同某种伦理答案。[S05]

## 二、编写方法

### 1. 从批准构思到可审校手稿

【流程规范】采用“构思自主 V2 → 正式开发基线 → HLD → LLD → 写作 → 分层评审与作者定稿”的推进方式。构思决定世界、人物、事件和故事线是什么；HLD 组织它们怎样组成小说；LLD 细化场景如何发生；写作完成连续正文。每次交接都携带来源、版本、约束和状态，不能仅凭自然语言摘要继续扩写。[S23] [S07] [S13] [S14]

V2 先以 B0 无损封装作者控制，再依次构建 S1 故事线、W1 世界、E1 环境、T1 事件、C1 角色，经过 Q1 独立审查，由 P1 组装机器构思包、H1 忠实呈现给作者。P1 与 H1 不获得新增故事事实的权力；旧开发地图也不能作为正式 V2 生产技能生成完成凭证。[S07]

HLD 应从重新验证通过的正式开发基线进入，完成宏观结构、故事线编排、人物弧线、信息与视角、时空节奏及关键场景功能，再通过语义审查、LLD 消费验收、人审和最终准入。这里描述的是仓库规范中的目标流程；规范文件已冻结，不等于《断线》已完成这一轮生产或相关实现已取得发布资格。[S13]

### 2. 人机分工与受控修订

【流程规范】作者决定主题、价值取向和重大创作选择，批准构思、结构变更与最终手稿；编辑参与文学判断与修订方向。Agent 在授权范围内展开设计、组装场景上下文、起草与修订，并暴露缺失和冲突。连续性检查器检查事实与状态，语义评审者检查因果、人物、节奏和可读性；这些角色均不能代替作者授权。[S06] [S14]

写作以场景为工作单元：先确认批准版本与前序状态，再明确目标、阻力、选择、信息边界和退出状态；完成初稿后先过硬约束门，再做语义评审及定向重写，最后更新连续性账本、汇编与全书修订。结构、人物与叙述、语言节奏、校对依次处理，避免用润色掩盖结构问题。[S14]

### 3. 内容权威与呈现分离

【流程规范】构思机器本体以 canonical JSON 为下游内容入口，Markdown 是确定性规格或阅读投影，HTML 是人审呈现，样章仅供体验。P1 包与呈现冲突时，应判定呈现失败并退回修正，不能静默覆盖后继续交付。作者批准必须绑定当前机器包及人审版本，不能由页面已打开或 Agent 自评推断。[S06] [S07]

【当前权威口径】本快照保存的批准证据位于 `conception-approved/`。批准日期为 2026-08-17，run 为 `duanxian-conception-v2-20260811-18`；决定范围是 `conception`，决定为 `approved`，完成记录为 `ready`。本地可核对的作者决定、批准 HTML、完成记录哈希相符。这证明留存材料之间的相应绑定，不代表本次已重放全量生产链。[S02] [S03] [S04]

【未完成项】本快照的 Git 跟踪文件中未找到该项目完整的 `novel-conception-package.json`、`development-handoff.json` 或 `hld-completion.json`；批准版 README 也说明运行账本与历史尝试不入 Git。因此本文件可引用批准报告整理目标，但后续正式开发仍须取得并重验绑定的机器包、基线及运行证据，不能从本文件反向重建缺失本体。[S02] [S04] [S06] [S13]

## 三、边界

### 1. 内容与系列边界

【当前权威口径】本部聚焦 R-07 的诞生、新关系、公共责任与当前实例关停。C、M 两国的有限合作、人质危机、实验权限和亲属保护共同施压；现实团队阻止袭击，R-07 的存在困境仍需单独处理。第一部不裁决法律身份、重载真假和长期互信，静态封存不是活动备份。[S05]

【历史/旧链口径】意图卡提出三部曲：第一部独立闭环，第二部涉及主动创造与长期相处，第三部涉及规模化社会后果。更早 PRD 对后两部的安排不同，七月 proposal 又曾不建议系列钩子。故当前只能据批准版保留未来入口，不在本目标文档冻结续作内容，更不能借续作复活取消本部代价。[S08] [S15] [S16] [S05]

### 2. 阶段与创作自由边界

【流程规范】判界以决定的性质为准，而非文件名：改变世界规则、主要事件或核心人物事实，须回构思；安排宏观位置、依赖、视角和揭示顺序，属于 HLD；细化场景动作、对白条件、感官材料，属于 LLD；形成可发表叙事文字，属于写作。HLD 不能提前写正文，LLD 和写作不能悄悄补足缺失的高层设计。[S13] [S14]

开发自由应是明确交付的范围，例如局部措辞、合法的场景进入方式和不改变事实的表达；它不是填补任何空白的许可。重大 POV 调整、因果改写、终局变化和未决身份的裁决，必须形成变更请求、退回责任阶段并取得相应批准。[S23] [S13] [S14]

### 3. 防漂移与历史隔离

【历史/旧链口径】七月 proposal 的 boundary ledger 记录来源、保留项、禁止项和开放问题，是边界显式化的历史例子。【流程规范】V2 的正式防漂移依靠作者基线、`authority_partition`、控制点来源、派生值哈希和 `open_items`；交接必须区分硬约束、开发自由与必须询问项。不能把旧 ledger 的内容直接升级为当前控制，也不能让下游改写前序 canonical 模型。[S16] [S07] [S13]

【当前权威口径】项目导览明确以批准构思为准，旧 proposal、PRD、HLD 属于历史链资产。【历史/旧链口径】2026-07-13 旧 HLD 的入口报告是 `pass_to_hld`，manifest 收敛状态仍为 `pending_hld_human_review`；报告明确人审确认前不得进入 LLD。它们既不是 V2 HLD 完成证据，也不能被早期设计文件中的“已完成”或 `pass` 字样覆盖。[S01] [S17] [S18]

## 四、约束

### 1. 人物、世界和事件硬约束

【当前权威口径】以下要求均可在批准人审报告中定位，应在后续场景设计与正文检查中逐项落实。[S05]

| 控制面 | 必须保持的事实 | 禁止的捷径 |
| --- | --- | --- |
| 主体与记忆 | R-07 由顾衡记忆启动，形成自己的判断；顾衡已经死亡 | 将新决定归给顾衡，把片段记忆当客观录像 |
| 感知与接口 | 无当前视觉、听觉、身体和自主移动能力；通过文字接触外界 | 赋予实时视听、具身体验、读心或直接现实行动 |
| 权限 | 启动、运行、交互、核验、行动、关停与保管分别承担责任 | 沈逾独自启动项目，或 R-07 靠输出自行获得权限 |
| 危机因果 | 线索由专家、硬件与授权链复核，现实团队完成阻断 | 一句情报直接关闭袭击，以任务成功免除实验伤害 |
| 关系 | 顾衡旧记忆与 R-07 新感情分开；亲属保有主体性 | 把告别改写成旧爱复活，默认程予安与 R-07 是夫妻 |
| 信息分层 | 行动层用于公共安全，原因层按必要范围保护 | 为保护亲属阻断救人，或以公开需要取消所有访问边界 |
| 终局 | 当前实例关停且无活动备份；未来加载需重新许可 | 活动副本、无损复活保证、两国自动恢复互信 |

这些限制也约束人物的一致性：沈逾的专业能力不能变成对 R-07 内心的全知；工程师能确认实例状态，不能证明人格连续；授权者能批准行动，不能代替个体裁定伦理答案。误解可成为剧情，但叙述必须区分角色判断、已知事实与未决问题。[S05]

### 2. 叙事契约与禁止事项

【历史/旧链口径】2026-07-21 叙述契约 v1.1 给出可执行的叙事硬规则：沈逾限制第三人称为主；顾衡仅有开端外部线；R-07 在终止计划形成前可有有限内部片段，旧编号 C5 后永久关闭该内部 POV。记忆由当前文字触发、片段式且可中断；已发送、未发送、删除和等待必须区分，不能让角色知道未收到的内容。[S09]

同一契约要求公平隐瞒：读者凭真实外部证据理解终止意图，不能靠伪造内心或压住角色已知事实制造谜底；表达准确克制，技术说明服务选择与核验，“连接／断线”每次出现都承担实际功能；禁止旁白裁决终止正确与否、用爱情或技术取消伦理问题，以及可辨识地模仿在世作者文风。[S09]

【未完成项】这些过程规则不能整套宣称已与当前 P1 完成绑定：同目录访谈简报引用的意图卡、主体定义等版本已不同于留存 Markdown，且该简报自身是 `awaiting_author_review`。应保留规则及来源供正式基线对照，尤其核验 C5 等旧编号映射。批准报告中的“十条故事线”与旧契约的“启动后共同主线”也不能直接等同或互相删改：前者是故事架构描述，后者是叙述组织要求，具体协调属于经过准入的 HLD 工作。[S20] [S09] [S05] [S13]

### 3. 科学、机器与授权约束

【历史/旧链口径】科学背景稿和技术系统稿提供过记忆、意识及设备描述，但包含理论推演与虚构延伸，不能作为现实可行性已获证明的依据；早期技术稿中的越权访问、活性转移细节，也不能覆盖批准版能力和权限限制。本目标文档仅分析仓库材料，不新增外部科学结论。[S19] [S21] [S05]

【流程规范】机器门禁应阻止错 run、旧 completion、未覆盖控制点、悬空引用和权限越界。硬约束失败不能以文学评分抵销；Agent 无权推断作者批准，结构性事实依赖缺失也不能靠临时设定补齐。需要变更时记录来源、影响和责任阶段，修复后使受影响旧版本失效并重新验证。[S06] [S07] [S14]

## 五、成果设计

### 1. 面向三类使用者的交付物

【流程规范】构思成果应同时有机器本体、人审呈现和完成凭证。机器包包括 `novel-conception-package.json`、确定性规格、跨模型索引、追溯矩阵和开发 handoff；人审包包括 JSON、Markdown、离线 HTML、非权威样片及独立忠实度审查；准入包包括作者决定、最终 completion、validation 和最新状态。三者需要指向同一版内容，不能只交付一份易读网页。[S06]

HLD 相应交付机器包、规格、跨索引、追溯矩阵、`lld-handoff.json`、消费验收和作者批准后的完成凭证。写作阶段则交付场景正文、计划卡、连续性账本、评审与修订单、汇编手稿和 `manuscript-manifest.yaml`。因此“canonical JSON 权威”针对构思和 HLD 的内容模型，不意味着把最终小说正文写成 JSON，也不替换开发阶段规定的清单载体。[S13] [S14]

【当前权威口径】仓库现有批准目录保存作者决定、构思完成记录及人审报告三种格式。【未完成项】它是已批准构思的留存交付证据，不是全量运行目录；项目导览还将小说正文标为草稿。当前不能据此宣称整部小说或其正式 HLD、LLD、发布手稿已经验收完毕。[S01] [S02]

### 2. 分部、章节与覆盖目标

【当前权威口径】批准报告用八个推进阶段呈现故事，并概括十条故事线、17 名角色和 43 个主要事件。这些是批准呈现中的结构与规模信息，不是章节数，也不应被转换为每人同等篇幅或每事件一章。[S05]

【历史/旧链口径】旧开发地图 M01—M10 明确是十个必要功能单元，不是十章；旧 PRD 的四阶段、旧 HLD 的 K1—K10、六月构想的双线章节估算均属于各自版本。【未完成项】本次材料不足以确认最终部数、章数、每章字数和全书总字数，应由正式 HLD 按覆盖与节奏需要确定，再由 LLD 拆分场景，不能为凑固定数量改变故事。[S10] [S15] [S22] [S13]

【推断】可用批准报告中的推进关系检查结构目标：前史与接受职责建立启动条件；主体形成与新关系累积伦理代价；人质和威胁推动分层交付及现实核验；阻断后的告别和余波完成本部闭环。这样的检查关注每段是否改变选择条件，不预先规定幕数、章节或详略比例。[S05]

### 3. 质量基线

【流程规范】可交接成果必须让下游知道必须保留什么、可以展开什么、何处不能猜测，并能追溯到批准来源。合格正文要让人物的行动产生可识别的局势变化，名称、时间、知识和物件状态连续；情感与主题由选择及后果承载。单纯篇幅达标、术语完整或语言流畅，都不足以证明作品合格。[S06] [S13] [S14]

【历史/旧链口径】覆盖矩阵与地图自检展示了把控制义务映射到单元的方法，例如权限区别、文字感知、核验链、终止与重载边界。后续应针对当前正式 ID 重建这种覆盖关系，不能将旧矩阵的 `covered` 直接复制为新版验收结论。[S11] [S12] [S07]

## 六、验收标准和方法

### 1. 作者批准硬门

【流程规范】构思决定只有 `approved`、`revise`、`rejected` 三种，不得预选或由 Agent 代填。只有当前生产状态为 `development_status=ready`，且最终完成记录通过正式 validator，才能声明构思阶段完成；等待作者、活动 return、仅有 HTML 或被否决均不得放行。HLD 另有自己的作者门和 `lld_ready` 准入，构思获批不能替代它。[S06] [S13]

【当前权威口径】《断线》留存决定是 `approved`，范围限于构思；完成记录绑定 B0、S1、W1、E1、T1、C1、Q1、P1、H1 九个阶段 completion。【未完成项】本次未取得完整运行链，不能声称重新执行了最终 validator。正式验收者应按记录定位生产证据，验证当前状态及路径/hash 闭合；这项复验要求不推翻已有批准记录。[S03] [S04] [S06]

### 2. 机器验收、消费测试与反向验证

【流程规范】机器验收分为可解析、可追溯、可复现和可消费四层，至少执行下列检查；每个结果须保留输入版本、实现版本和失败定位。[S06] [S07] [S13]

| 检查 | 合格标准 | 失败处理 |
| --- | --- | --- |
| Schema 与引用 | 必填字段、稳定 ID、引用对象、权限分类及控制覆盖完整 | 返回拥有该对象的阶段 |
| 确定性与版本 | manifest 清单和 SHA-256 匹配；相同输入的确定性组装结果字节一致 | 修正组装或来源，旧结果失效 |
| 语义覆盖 | 关键因果、动机、例外、代价与开放状态未被遗漏或改变 | 返回最早产生偏差的责任阶段 |
| LLD 消费能力 | 独立消费者仅凭 handoff 重建全部工作单元、顺序、边界与验收条件，无须猜补 | 补齐责任产物后重新交接 |
| 准入一致性 | 作者决定、机器包、人审包、handoff、完成记录和最新状态同版，无活动退回 | 停止下游准入 |

HLD 消费测试应先隔离读取 handoff 并密封重建结果，再由另一上下文对照正式机器包检查忠实性；不能让消费者靠原包或旧稿补齐 handoff 缺口。语义审查通过不等于消费验收通过，两者都是必要证据。[S13]

构思最终契约还要求反向验收：删除源 completion、混入旧 run 或旧包、保留 ID 却改动因果、将样片升级为事实、变更批准 HTML、让 revise/rejected 生成完成记录等，都必须失败并阻止放行。Schema 通过、hash 相同或页面可打开，只证明部分结构和版本条件，不能单独证明语义忠实。[S06]

### 3. 文学质量、人审与全书定稿

【流程规范】构思人审应在不超过十分钟的默认阅读预算内，让作者看清世界、故事线、人物、样片和决定入口。独立忠实度审查须逐元素检查身份、范围、结论、强调、权威和决定一致性，不能把重要例外藏入审计字段，也不能把尚未决定的未来讲成确定事实。[S06]

正文先过客观门，再按场景 rubric 审查：功能与价值变化 20 分、人物能动性 20 分、视角信息与连续性 15 分、冲突节奏与因果 15 分、声音与可读性 15 分、环境与情感外化 10 分、修订完成度 5 分。通过条件是无客观 blocker、总分至少 80、前四项各不低于满分的 70%，且作者无未处理的重大异议；不能用总分掩盖人物或因果失效。[S14]

全书还需检查宏观结构、人物弧、线索闭合、语言一致性和人工校对。作者至少批准代表性场景的声音与密度、结构性变更、宏观修订方向及最终手稿；只有全部准入与批准条件成立，才可标记 `released`。目前留存的构思批准只完成其中一个阶段。[S14] [S03]
