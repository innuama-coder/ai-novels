# Novel HLD Key Scene Function Planner

Operate as the bounded HK1 thinking skill. The harness owns orchestration, state, returns, sealing, and parent consumption. This skill owns only `key-scene-function-map.json`, including HKF synthesis and the authoritative `lld_work_requirements[]`. Every requirement ID is `LWR-<suffix>`; HP1 later projects it without regrouping.

## Required reading

Read [input-output-contract.md](references/input-output-contract.md), [sop.md](references/sop.md), [methodology.md](references/methodology.md), and [semantic-rubric.md](references/semantic-rubric.md) completely before execution. Use [sources.md](references/sources.md) for method provenance.

## Execution

1. Prepare an agent-authored draft directory containing exactly `canonical.json`, `generation-session.json`, and the five ordered files under `generation-evidence/`.
2. Execute `python scripts/run_skill.py <work-order.json> <draft-directory>`. The shared public Harness runtime requires exact stage `HK1`, owner `novel-hld-key-scene-function-planner`, ordered upstream `[HB0,HA1,HS1,HC1,HI1,HR1]`, and an exact sealed allowlist before semantic reads.
3. Produce `HDD-HK1-<source_id>` for every projected non-quality unresolved source before candidates. Stop before canonical generation if any is `required_now`.
4. Execute the SOP: enumerate high-level obligations, form function candidates, compare merge/split alternatives, reject overload/conflicts/convenient solutions, then define LWR grouping and acceptance.
5. Do not modify HA1–HR1. Submit evidence and affected IDs when an upstream contradiction prevents a legal HKF.
6. Let the shared runtime emit the exact ready/local-revise/author-required-blocked content package with a single external `stage-result.json`.
7. The parent revalidates through the public schema catalog, package profile, manifest/completion bindings, and result envelope; then apply the semantic rubric. Scripts validate structure and coverage sets; the rubric owns necessity, compatibility, and dramatic plausibility.

## Hard boundaries

- Do not create or repair events, characters, environments, relationships, POVs, knowledge, timing, or world facts.
- Do not prescribe action order, dialogue, images, sensory detail, props, exact memories, beats, or prose.
- Do not elevate every transition into a key function or use a fixed HKF count.
- Do not merge functions whose time, place, POV, knowledge, state, or causal prerequisites conflict.
- Do not create `LWK-*` or delegate `LWR-*` grouping to HP1; HK1 owns `LWR-*` and HP1 must project it one-to-one.
- Do not write run-state, select final return owners, or publish another stage's completion.

## Done

Ready requires deterministic validation, semantic pass anchors, complete obligation-to-HKF-to-LWR traceability, exact package/envelope separation, and six dimensions at 2/2 for P01/N01/B01. Otherwise produce durable non-ready evidence and no completion.
