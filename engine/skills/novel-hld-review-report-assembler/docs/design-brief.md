# Design brief

## Problem and outcome

HP1 is complete but optimized for machine consumption. HH1-A must organize its conclusions into an author-facing review model that supports an approval or revision decision within ten minutes without becoming a second HLD authority.

## Owner and boundaries

- Owner: HH1-A / `novel-hld-review-report-assembler`.
- Type: hybrid, thinking-dominant.
- Unique semantic source: current sealed HP1 package.
- Gate-only evidence: current HQ2 pass bound to the same HP1 hash.
- Out of scope: HLD repair, story-quality judgment, fidelity certification, HTML/SVG rendering, author decision, composite publication.

## Success

The report covers the seven frozen HLD domains, every display element resolves to HP1 source IDs and locators, all material controls remain locatable, the fixed budget is at most ten minutes, and HH1-B/HH1-C can consume it without guessing.

## Failure posture

Local organization, wording, visual selection, binding, or budget defects are `revise`. Missing HP1 conclusions are `blocked/upstream_defect`. Runtime failures preserve evidence. No non-ready outcome emits a completion.
