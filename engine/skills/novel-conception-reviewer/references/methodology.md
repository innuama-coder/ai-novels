# 小说构思交接审阅方法论

## 使用方式

本文件记录 R1 所采用的方法来源、适用检查和明确边界。来源用于形成通用审阅问题，不授权技能把任何框架写成小说事实，也不要求所有小说符合固定幕式、类型公式或商业市场标准。

检索日期：2026-07-24。

## 综合结论

### 1. R1 是验收，不是第二次设计

审阅对象是 D1 已经形成的构思合同、开发缺口和新增设计决定。R1 可指出矛盾、缺口、越界和开发风险，但不能用更好的创意覆盖原决定。D1 能在既有控制点内解决的问题退 D1；只有确实需要改变控制点时才回到上游拥有者。

### 2. 完整性是“有新增且关系完整”，不是字段数量

六区都存在仍可能不可开发。R1 必须检查：

- 世界规则是否真正约束人物和事件；
- 人物目标、压力反应和选择是否导致因果变化；
- 因果链是否支付承诺与结局；
- POV、读者知识和角色知识是否与事件顺序兼容；
- 开放项是否被允许保留而没有静默裁决。
- 每个自主缺口是否得到具体决定，而不是总结或建议；
- 每个决定是否比较真实方案，并进入至少一个单元和一个完整构思对象；
- 对抗是否会回应人物，关键选择是否具有吸引力与机会成本；
- 是否存在能瞬间消解冲突的便捷解法；
- 下游是否还被迫发明核心规则、动机或主线因果。

### 3. NDB 是导航视图，不是新权威

NDB 应优先引用控制点和 D1 单元，帮助开发者找到承诺、规则、人物、因果、信息和边界。它不重新概括出无法追溯的新事实，也不替代六份权威设计稿。

### 4. 自主价值必须单独证明

R1 必须能够明确回答“D1 相对访谈新增了什么，以及这些新增为何使小说更丰满、更严密”。如果只能列出控制点、同义改写或访谈节点，即使结构和哈希全部通过，也应退回 D1 修订。

每条设计决定按六维复核：

1. 必要性；
2. 与作者控制点的兼容性；
3. 因果或戏剧效用；
4. 具体到足以指导开发；
5. 没有夺取作者专属决定；
6. 仍为章节与正文保留自由。

### 5. 开发可用性必须通过任务证明

“看起来完整”不能证明可交接。不同于 D1 自测执行者的角色必须仅凭 D1 包完成故事承诺、自主增量、因果链、单元契约、自由边界、偏航识别、便捷解法攻击和场景计划八项任务，并引用真实 ID。

### 6. 结构真相、语义判断和作者批准分层

- 机器验证路径、哈希、集合覆盖、确定性输出和不可变绑定；
- R1 判断派生解释与跨域语义是否成立；
- 作者决定是否接受当前审阅结果进入开发。

三层均通过才形成最终 R1 completion。

### 7. 三域完整性必须检查关系，不以字段数量冒充

- 世界完整性由八类必要信息、实际运行系统与主要环境共同证明；信息说明世界是什么，系统说明人物与事件依据什么机制运行，环境说明这些行动发生在怎样的条件、感知、资源、访问和危险之中。
- 故事完整性由一条主线、至少一条支线和至少一条背景线的相互作用证明；支线和背景线必须改变主线的选择、信息、代价或结局。
- 人物完整性先由决定权、信息传递、能力形成、对抗执行、关系压力、行动执行和后果承担七类职责需求的完整处置证明，再由每位核心角色向外展开的至少三层人物路径及节点定义证明：层级按人物—人物关系的最短路径计算，不按亲密、行动、制度等主题分类；外延人物必须拥有自己的姓名、目标、边界、信息限制、受压行为和能动选择。

这些是构思开发深度的最低结构，不是类型公式。R1 关注每项是否具有因果作用、是否遵守作者边界、是否给下游留下表达自由，不以世界条目、人物数量或故事线数量越多越好。
