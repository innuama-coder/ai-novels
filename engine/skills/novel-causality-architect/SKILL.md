# 小说因果架构

## 任务边界

产出一份**因果故事线**，回答“在这些主体、关系和世界限制下，什么变化迫使谁作出什么选择；该选择又为什么使下一变化成为必要”。它把主体定义和角色选择模型转为可开发的主线骨架，不是章节表、分场大纲、时间流水账或 prose。

读取 [conception-phase.md](../../docs/ai-novel-workflow/conception-phase.md) 的“前五步共同交互协议”、[causal-methodology.md](references/causal-methodology.md) 和 [causal-storyline-template.md](references/causal-storyline-template.md) 后执行。

每个节点采用最小链条：

```text
既有状态/限制 → 主体尝试或选择 → 阻力、反转或代价 → 新状态 → 下一项不可回避的问题
```

只有“后来发生了”而没有前一节点的选择、规则后果或已建立条件，不构成因果节点。

## 输入与准入

| 输入 | 可使用方式 |
| --- | --- |
| 作者原始 idea | 作为待讨论的故事材料、既有设定线索与冲突来源；只有被意图卡、主体定义或作者当前明确确认/授权的部分，才能成为因果节点的硬前提。 |
| `intent-card.md` | 继承 `confirmed`、允许的 `provisional` 和授权范围；不得改写故事承诺、范围、结局性质或硬边界。 |
| `subject-definition.md` | 仅在交接状态为 `ready` 时继承核心选择、目标、代价、关系功能、世界压力及其状态；接受 `confirmed`、`provisional` 与在授权范围内的 `delegated` 决定，并保留其来源状态。 |
| `world-operating-contract.md` | 仅在交接状态为 `ready` 时继承世界规则、资源、权力、信息边界、压力机制和例外；不得为节点便利绕开它们。 |
| `core-character-design.md` | 仅在交接状态为 `ready` 时继承动机、形成链、压力反应、关系杠杆、变化边界和选择预测；不得为情节便利改写人物逻辑。 |
| 作者补充材料 | 标记为作者输入，说明它改变哪个节点或链接，再纳入当前组。 |

作者必须明确指定多份旧稿、HLD 或世界设定中哪一份是当前基线；文档的新旧、篇幅或细节多少不自动赋予权威。当前作者明确的修订可覆盖旧决定，但必须在输出中记录“被修订项 → 新基线 → 作者确认”。同一权威层的输入相互冲突时，或旧稿与当前基线的关系未指定且会改变因果链时，输出 `blocked`，不得拼接折中。

以下情况输出 `blocked`，说明最小缺口并退回上游：

- 主体定义没有可归属的核心选择、外部目标、代价或世界压力；
- 核心角色设计缺失、不是 `ready`，或无法解释关键选择；
- 意图卡、主体定义与核心角色设计在结局性质、主体选择或世界限制上冲突；
- 输入要求直接列章节/场景或写正文，却没有触发—选择—后果的控制点；
- 关键结果只能依赖巧合、未定义能力、没有前置条件的外部帮助或作者解释才成立。

不得从旧稿、原始 idea 或旧 HLD 静默补回会改变上游决定的情节。作者明确新增或意图卡授权的范围除外；此类决定必须标为 `confirmed` 或 `delegated`。

## 状态与交互

每次回复开头标明当前状态与决策组，不必重复整条因果线。

| 状态 | 含义与行为 |
| --- | --- |
| `exploring` | 正在理解一个因果控制点；先提问或澄清。 |
| `awaiting_confirmation` | 已形成候选链；只请求确认、修改或暂定。 |
| `confirmed` | 作者明确确认；冻结本组并转入下一组。 |
| `delegated` | 作者已授权 Agent 决定；记录为授权，不伪称作者确认。 |
| `provisional` | 作者明确允许暂定；记录影响范围与回看点。 |
| `open` | 尚未决定但不阻塞当前组；记录责任人与最晚决定时点。 |
| `blocked` | 缺少决定或存在冲突；停止推导，提出最小问题。 |

作者的普通补充不自动等于确认；只有“确认/就按这个/选择 A/暂定 A”等明确回应可冻结一组。意图卡授权 Agent 决定某类内容时，Agent 可建立 `delegated` 节点，但无权改变故事承诺、结局性质、主体选择或世界硬边界。

首轮展示：可继承的已确认边界、当前决策组、唯一学习目标、已知因果缺口，以及一至三个短问题。每轮遵守：

1. 说明本轮只决定哪段因果关系，不决定场景、章数或叙述方式。
2. 区分作者确认、作者新输入、Agent 推断/授权与开放项；指出冲突。
3. 先开放提问；必要时给最多三个、在同一因果控制点上不同的候选。
4. 说明候选会改变谁的选择、何种代价、下一节点的必然性或结局含义；不得用“更好看”推销。
5. 明确请求“确认、修改还是暂定”；等待确认时不跳到下一组。
6. 更新节点表和链接台账；回显冻结项、开放项与下游影响。

信息发现只有在改变角色可选行动、风险、关系或代价时才能成为转折；“发现真相”本身不是因果解释。

## 四个因果决策组

### A. 结局状态与因果承诺

**学习目标**：确定结束后哪些状态不可逆，以及结局如何回应意图卡，而不重写上游结局性质。

获得：结局前后状态变化、各核心主体的结局位置、被有意保留的问题、系列接口的功能边界。

不获得：最后一章的动作、措辞、画面或具体信息披露顺序。

检查点：结局是主体在既定限制下的选择后果；能回收触发事件提出的问题。

### B. 危机与高潮选择

**学习目标**：倒推什么使结局选择不可避免且有真实代价。

获得：危机中的互不兼容选项、被迫选择的主体、高潮行动、立即后果，以及其他退路为何失效。

危机必须让主体在两种有代价的路径间取舍，而不是“是否做显然正确的事”。高潮是主体把危机选择付诸行动，不是反派失败、信息自动送达或没有前置条件的外力救场。已由先前选择、关系、资源或世界规则建立的协作可以帮助执行选择，但不能替代它。

检查点：移除危机或替换高潮选择会改变结局性质；高潮后可直接推出结局状态。

### C. 触发、阶段目标与关键转折

**学习目标**：从结局倒推开端，建立有限的状态变化链，而不是按日期罗列事件。

获得：触发事件、初始目标、至少一次使旧策略失效的中段转折、临界转折，以及各阶段的新目标或限制。

为每个节点填写 `前提 → 选择/尝试 → 结果/反转 → 状态变化 → 下一目标或问题`。节点可以是发现、失败、关系变化或规则后果，但必须说明主体的回应如何导致后续。

检查点：每个转折让主体的可选行动、关系位置、风险或信息责任至少一项不可逆变化；删除任一关键节点时，能指出后续哪个选择失去前提；时间压力只能作为已定义规则的后果，不能替代人物选择。

### D. 支线功能、因果审计与交接

**学习目标**：让支线和未公开事实服务主线因果，并审计整条链能否交给叙述契约与开发地图。

只保留能完成至少一项功能的支线：增加主线代价、提供/撤销关键资源、改变核心关系、反照主题选择、兑现世界规则或为系列接口留出功能。否则合并、降级或删除。

对每条秘密区分：**在故事事实中何时改变选择或代价**与**何时让读者得知**。前者属于本 skill；后者交给 `novel-narrative-contract-designer`。

检查点：主线每个链接都可用“因为……所以……”复述；每条支线有主线功能；没有依赖未定义能力、巧合、信息自动解决问题或未支付的结局收益。

## 因果审计

确认前检查：

| 检查 | 通过条件 |
| --- | --- |
| 选择归属 | 每个关键结果归于核心主体的选择/尝试，或已定义世界规则的必然后果。 |
| 前提可追溯 | 节点所用资源、知识、权限、关系或风险已在更早节点建立。 |
| 状态改变 | 节点后至少一项外部局势、关系、可选行动、信息责任或代价不可逆变化。 |
| 代价真实 | 高潮与结局没有无损满足互斥目标。 |
| 升级而非重复 | 下一阻力迫使新策略、新信息责任或更高代价。 |
| 支线有用 | 每条支线指向一个主线节点和具体功能。 |
| 外援可归因 | 外部协作/救援若参与结果，已说明是谁在何时以何种选择、资源或规则建立其条件，且它不替代高潮选择。 |
| 边界合规 | 不新增越过意图卡/主体定义/核心角色设计的能力、结论或世界规则。 |

若因果可行而 POV、谜底何时揭露、叙述顺序未定，不要阻塞：在交接中标为 `narrative-contract` 决策。若未定项改变主体为什么作此选择，才阻塞。

## 访谈计划与完整记录

在第一条实质问题前，读取 harness `workflow.md`，向作者展示 I4 的四组、`plan.v1.json` 已核定的**精确**互动问题数、分钟数、完成条件和 blocker，并记录输入版本。内部容量估计可以补充展示，但不得替代作者可见的访谈计划；每轮刷新已用问题数、剩余预算和预计剩余时间；变更计划必须由作者明确确认并写入新的 `plan.vN.json`。

本 skill 只能在 harness I4 中运行：会话写入 `<project>/interview-sessions/I4/<session-id>/`，先创建 `plan.v1.json` 并向作者说明精确问题数和预计时长；每轮立即追加 `events.ndjson`，运行验证器并重建 `report.md`。结束时生成因果故事线和 I4 `stage-completion.json`；不得以事后总结覆盖作者原话。因果审计发现世界规则/资源/权限无法支撑节点时，必须按 harness 回退至 I2，而非在本 skill 补设定。

## 输出与完成条件

在写入 I4 `stage-completion.json` 前，生成并校验 `control-projection.json`。使用稳定的 `CAU-` ID，将因果链、触发条件、阻力、行动、代价、状态变化、不可逆后果、边界和开放项逐项无损投影。每项必须绑定 `causal-storyline.md` 的精确行范围及文本哈希，并忠实标记 `hardness`。completion 使用 `contract_version: "2.0"` 并哈希绑定投影；专用 validator 未通过时不得交接。

投影中的每项控制必须只绑定因果稿中的一个完整 H2/H3 章节；`heading` 与字符串 `value` 分别原样对应章节标题和去除首尾空行后的正文。不得使用多段范围、局部摘录、结构化改写或哈希正确的近义转述。

完成或被阻塞时生成 `causal-storyline.md`，遵循模板并包含：

- 继承的故事承诺、主体选择、角色压力模型、世界限制和结局边界；
- 触发、阶段目标、关键转折、危机、高潮选择与结局节点；
- 主线因果链接台账、主体状态轨迹、支线/秘密功能；
- 决策、来源、授权、开放项和 blocker；
- 给 `novel-narrative-contract-designer` 与 `novel-development-map-designer` 的交接；
- A–D 四组的最小会话记录。

仅当满足以下条件时，输出可交接的 `confirmed`、`delegated` 或 `provisional` 故事线：

1. 结局、危机和高潮选择均已确认或由作者明确授权；
2. 触发到结局的每个关键节点都有前提、主体回应和状态变化；
3. 每位核心主体至少一次以选择改变主线，且高潮主体与危机主体一致或已解释因果接力；
4. 每条支线有主线功能，所有秘密区分事实影响与读者披露责任；
5. 没有会改写因果链的 `open` 项；此类项必须 `blocked` 或来自明确授权；
6. 没有靠巧合、新能力、无前置条件的外部帮助或作者解释完成的关键链接。

否则输出 `blocked`，指出应由作者或上游回答的最小问题。

## 交接与禁止项

交给 harness I5 的 I4 `stage-completion.json`：叙述契约决定读者何时、从谁的视角知道这些因果事实，但不得改写故事事实、主体选择或结果。不得直接交给开发地图；开发地图只能在 V1 通过且作者批准 V2 后由 harness 启动。

不得输出章节列表、场景表、分镜、逐段动作、对白、感官细节或连续小说正文；不得用固定三幕比例、节拍数量或模板名替代因果证明。
