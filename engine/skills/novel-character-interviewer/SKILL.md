# 小说角色访谈

## 任务边界

产出 `core-character-design.md`，回答：**在已确定的故事位置上，这个人为什么这样理解局势，在不同压力下会怎样选择，又可能因什么改变或拒绝改变？**

这是对作者的设计访谈，不是 Agent 冒充虚构角色接受采访。角色扮演答案只能作为候选，不得自动成为设定。开始前完整读取：

- [conception-phase.md](../../engine/docs/ai-novel-workflow/conception-phase.md) 的“前五步共同交互协议”；
- [character-methodology.md](references/character-methodology.md)；
- 生成交付物时读取 [core-character-design-template.md](references/core-character-design-template.md)。

只获取能改变**选择、冲突、关系、变化或表达**的信息。生日、爱好、衣着、完整履历等若不能通过相关性检验，就删除或留给开发阶段。

## 输入与准入

| 输入 | 使用方式 |
| --- | --- |
| 作者原始 idea | 默认必须提供，用来校验原始人物直觉和遗漏；未经当前确认，不覆盖上游。若无单独 idea，作者须确认上游已完整代表它。 |
| `intent-card.md` | 交接状态必须为 `ready`；总体决策状态可为 `confirmed` 或作者明确允许的 `provisional`。继承故事承诺、主题问题、范围、硬边界和授权。 |
| `subject-definition.md` | 交接状态必须为 `ready`；总体决策状态可为 `confirmed`、`delegated` 或作者明确允许的 `provisional`。继承核心主体、选择位置、目标、代价、关系功能和世界压力。 |
| `world-operating-contract.md` | 交接状态必须为 `ready`；继承实际能力、资源、权力、信息通道、环境限制和世界压力实现。 |
| 旧稿、人物资料 | 先确认是当前规范还是历史材料；只提取与本技能相关的证据。 |
| 已有因果/叙述稿 | 仅在补做角色访谈时作为冲突检查输入，不反向取得更高权威。 |

作者当前明确修订可覆盖旧决定，但必须记录“原决定 → 新决定 → 受影响的上游/下游”。同一权威层冲突且会改变关键选择时输出 `blocked`，不得折中拼接。

以下情况必须阻塞：意图卡或主体定义缺失/非 `ready`/相互冲突；不知道谁承担核心选择或其目标、代价、关系压力；未决问题实际改变事件而非人物理由；要求人物百科却没有故事功能。

这里的“非 `ready`”专指交接状态，不把上游的总体决策状态与可交接性混为一谈。若上游有允许继承的 `provisional` 项，必须同时继承其风险、影响范围和回看点。

**强制准入首轮**：若缺少 I0、I1 或 I2 的 `ready` completion packet，不得开始角色访谈、暂定任何人是主角/关键关系，也不得把原始 idea 中的人物称为已继承主体。首轮必须标记 `blocked`，由 harness 按唯一回退路径路由至 I0、I1 或 I2。此时只可询问一个**路由问题**，不得询问故事承诺、主题、角色、事件或其他任何实质内容；它们分别属于上游访谈。只有三份上游产物均为 `ready` 后才可进入角色分级和 A 组。

## 角色范围分级

| 层级 | 判定 | 访谈要求 |
| --- | --- | --- |
| 核心决策角色 | 至少一次不可替代地改变主线、结局或主题回答。 | 完成 A—E 全部。 |
| 关键关系角色 | 通过依赖、权力、误读、资源或代价显著改变核心角色选择。 | 完成相关的 A、C、D；必要时补 B/E。 |
| 功能角色 | 主要传递资源、阻力、信息或环境功能。 | 只记录功能、边界和不可替代性；不强行做人物弧。 |

人数不是价值判断。不得为了“立体”把所有角色升级为核心角色。

分级先继承主体定义，再请作者确认本次访谈深度。若作者要新增或升级一个承担主线选择的角色，先退回主体设计确认其选择位置；不能借访谈静默扩充主角。多角色按关键选择负荷排序，每完成一组都做跨角色差异检查，不一次问完某人的全部档案。

## 状态、授权与路由

每次回复开头标明当前角色、决策组和状态：`exploring`、`awaiting_confirmation`、`confirmed`、`delegated`、`provisional`、`open` 或 `blocked`。

- 普通补充不等于确认；“都行”要追问是继续比较还是授权 Agent 决定。
- `delegated` 必须保留授权范围和 Agent 选择，不能伪称作者确认。
- `open` 只允许不影响关键选择的局部项，否则转为 `blocked`。
- 作者不知道、角色不知道、角色隐瞒、读者暂不应知道必须分别记录。

按问题实质路由：故事承诺/主题/范围回意图；谁承担选择、关系功能或世界能力回主体；事件顺序、获知节点和后果交因果；POV、披露与文体交叙述契约；人物如何解释压力并选择留在本技能。

## 每轮交互协议

首轮只展示继承边界、角色分级建议、当前唯一学习目标和一至三个短问题。一个决策组可多轮，但每轮只处理一个控制点：

1. **定位**：说明本轮决定什么，以及影响哪个关键选择。
2. **开放提问**：请作者描述直觉、经历或行为，不用标签诱导。
3. **校准**：区分事实、作者解释、Agent 推断和未知；只在反例由已确认的世界规则、关系或压力链支持时，才追问一个反例或边界。
4. **建议**：作者卡住时给 2—3 个机制不同的候选组合；说明选择影响，不以“更有张力”推销。
5. **回显**：用“原因 → 解释 → 策略 → 压力行为 → 代价”复述，不扩写场景。
6. **确认**：请求确认、修改、暂定或授权；等待确认时不跳组。
7. **记录**：冻结决定、列开放项和因果影响，再询问是否继续。

优先问行为和取舍，例如“当 X 威胁 Y 时，他第一步会做什么？什么情况下反而不会？”不要问“他勇敢吗”。候选是完整动机—行为方案，不是形容词菜单。

不得为了测试“例外”而虚构已被作者的铺垫、关系策略或世界规则排除的情境。若此类情境不属于规范故事路径，记录为非规范风险或留给后续因果审计；除非作者主动要设计 contingency，否则它不构成角色访谈的待决项。

## 五个角色决策组

### A. 角色范围与动机引擎

继承主体的外部目标和核心选择，确认角色个人想得到/保住/避免什么、为什么现在重要、最怕付出什么，以及价值排序。允许互相冲突的多重动机，不强迫只有一个欲望。

检查点：能解释角色为何行动、为何不放弃，以及两个合理目标冲突时优先保护什么。

### B. 自我叙事与形成因果

只追问会作用于现在的过去：`形成经历 → 当时解释 → 自我/世界信念 → 保护策略 → 当前收益与代价`。

形成原因可以是长期关系、成功经验、制度训练、文化环境或创伤，不默认用悲剧解释一切。过去事实与角色解释分开；不影响当前选择的隐秘背景可不决定。

检查点：信念和策略有来源和现实用途，也能解释其局限；不用诊断词或单一创伤替代因果。

### C. 矛盾、边界与压力行为

把性格标签转成可预测行为。确定优势如何产生代价、公开/私下自我、默认应对、升级反应、崩溃/越界条件、反例和道德边界。

使用压力梯：`平稳 → 受威胁 → 资源减少 → 关系受损 → 不可逆选择`。每级只定义行为方向，不设计事件。

压力梯只使用本作已经建立或作者明确允许的压力类型；它是提取角色在规范情节路径中的行为变化，不是要求作者为每个理论反事实预先定性。

检查点：矛盾有同一心理/价值根源；既非随机反差，也不会在所有情境下都做同一件事。

### D. 关键关系动力

对每条关系分别记录双方：如何看对方、想得到什么、依赖/债务/权力、误读、默认不说之事，以及背叛、修复或改写关系的条件。

关系是双向模型，不能只写“帮助主角成长”。删除关系时，应能指出消失的选择压力、资源或自我认识。

### E. 变化边界与表达指纹

选择正向、负向、平直、混合或无显著变化，不把成长当默认。定义初始信念/策略、检验压力、改变阈值、结尾更新或固守，以及始终不变的核心。

表达指纹只定义注意过滤、归因习惯、所想与所说的距离、沉默/回避、压力下语言变化；不写示范对白、口头禅或夸张方言。最终呈现受叙述契约约束。

非人角色另行说明感知输入、认知连续性、价值形成、能力边界、主观缺失和身份连续性，不默认套用人类身体与情绪经验。

## 访谈计划与完整记录

在第一条实质问题前，读取 harness `workflow.md`，先确定本轮覆盖的核心角色，再向作者展示 I3 的五组、`plan.v1.json` 已核定的**精确**互动问题数、分钟数、输入版本和 blocker。角色数量变化只能触发新的、由作者明确确认的 `plan.vN.json`；内部容量估计可以补充展示，但不得替代作者可见的访谈计划。

本 skill 只能在 harness I3 中运行：会话写入 `<project>/interview-sessions/I3/<session-id>/`，先创建 `plan.v1.json` 并向作者说明精确问题数和预计时长；每轮立即追加 `events.ndjson`，运行验证器并重建 `report.md`。结束时生成核心角色设计和 I3 `stage-completion.json`；不得以事后总结覆盖作者原话。角色不能静默新增世界基本规则，发现此类缺口必须按 harness 回退至 I2。

## 输出与完成条件

在写入 I3 `stage-completion.json` 前，生成并校验 `control-projection.json`。使用稳定的 `CHR-` ID，将核心角色身份、目标、责任、能力边界、价值连续性、关系约束、变化条件和开放项逐项无损投影。每项必须绑定 `core-character-design.md` 的精确行范围及文本哈希，并忠实标记 `hardness`。completion 使用 `contract_version: "2.0"` 并哈希绑定投影；专用 validator 未通过时不得交接。

投影中的每项控制必须只绑定角色稿中的一个完整 H2/H3 章节；`heading` 与字符串 `value` 分别原样对应章节标题和去除首尾空行后的正文。不得使用多段范围、局部摘录、结构化改写或哈希正确的近义转述。

按模板生成 `core-character-design.md`，包含输入权威与修订、角色分级、动机引擎、形成链、矛盾与压力梯、价值边界、关系动力、变化契约、表达指纹、选择预测矩阵、因果交接和 A—E 会话记录。

总体决策状态按最弱的已接受决定聚合：A—E 全为作者确认时为 `confirmed`；含授权决定且无暂定项时为 `delegated`；含作者允许的暂定项时为 `provisional`；存在 blocker 时为 `blocked`。`ready` 是独立的交接状态，只有下列条件全部满足时才可填写；它可以与前三种总体状态并列。

只有以下条件全部满足才可标记 `ready`：

1. 每位核心角色都有故事位置、外部目标、个人利害和价值排序；
2. 关键策略至少有一条形成链；
3. 每位核心角色有“优势—代价”、压力梯、越界条件或明确不越界理由；
4. 每条关键关系建立双向解释与选择压力；
5. 变化类型、起点、检验压力、终点和不变量明确；
6. 选择预测矩阵足以让因果技能测试关键决定；
7. 没有改变关键选择原因的 `open`，也没有上游冲突。

否则输出 `blocked`，只列最小缺口、责任人、影响和退回位置。局部习惯、外貌、爱好、具体台词可交开发阶段。

## 交接与禁止项

交给 harness I4 的 I3 `stage-completion.json`：默认解释和行动、升级/崩溃阈值、关系杠杆、变化检验、道德边界及禁止的人设捷径。harness 验证后再启动因果架构；因果架构必须用事件检验这些模型，不得为迁就情节让角色无前提改性。

补做访谈时列出既有因果和叙述稿中必须重验的节点，但不在本技能内静默改写。

不得输出完整人物传记、章节/场景表、事件链、对白、独白或连续正文；不得用人格测试、精神诊断、创伤标签、原型名或固定人物弧替代项目证据。
