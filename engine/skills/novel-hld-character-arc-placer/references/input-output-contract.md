# HC1 input and output contract

## Input gate

Require public work-order/input-gate schemas, `stage=HC1`, the exact skill
owner, `input_gate_ref`, and ordered upstream artifactReferences
`[HB0, HA1, HS1]`. Consume HA1 coordinates and HS1 storyline segments, unit
matrix, typed connections, and event placement only through current completion
roles. All person, relationship, motivation, ability, permission, knowledge,
event, and outcome facts must resolve to HB0-indexed authority.

The exact fileReference allowlist closes over state, baseline bindings,
source-lineage values, all upstream main/manifest/completion/validation and
protocol files, and every file declared by each upstream manifest. The work
order and self-hashing gate are the only bootstrap exceptions. Missing, extra,
stale, or gate-drifted references fail before unauthorized nested reads.
`unresolved_projection[]` is an ordered source-ID string list and HDD evidence
must cover it exactly in that order.

Read only gate-allowlisted sources and current upstream packages. Do not read
quality sources, chat, report prose, old HLD, or downstream artifacts.

## Canonical invariants

- every core character in the participation register has an arc state model;
- the path contains start, pressure, choice, cost, and result functions;
- each arc step binds an existing narrative unit, storyline segment, event,
  pressure, choice, cost, and consequence;
- relationship steps bind exactly two existing characters and record both
  pre- and post-states;
- event alignment names the responsible participant for every key result;
- every participation `responsibilities[]` item is a natural-Chinese functional
  duty sentence beginning with `负责`, with no unexplained English prose, and never asserts
  death, survival, consciousness, recovery, or another lifecycle state; those
  facts are expressed through ordered chapter agency. Single-letter story names
  such as C, M, and R-07 remain legal;
- every participation duty is an in-world responsibility: a concrete action,
  protection, decision, verification, prevention, or delivery owned by that
  person or institution. It never describes plot movement, suspense, conflict
  maintenance, failure paths, setup/payoff, reader effect, or another
  out-of-world design function;
- in return-resolution mode, the sealed target group is non-empty and owned by
  HC1. A `HAS-PARTICIPATION-*` group is
  the complete ordered `character_participation_register`, with every stable ID
  bound to its corresponding existing `CHR-*` identity. A `HAS-AGENCY-*` group
  resolves to exactly one existing chapter agency contract per affected ID in
  sealed chapter order. One narrow combined form is legal when the same defect
  requires both chapter information authority and its consuming character-arc
  step to change: ordered `HAS-AGENCY-*` IDs followed by ordered `HAS-ARC-*`
  IDs. It requires an accepted return base and freezes every non-target
  semantic object and the complete authority partition. Derivation-claim
  inventory, order, stable IDs, and target locators remain exact; only a claim
  already targeting `/chapter_agency_contracts` or `/arc_steps` may refresh
  `source_refs` and `value_sha256`, subject to the public authority and hash
  checks. All other derivation claims remain byte-for-value exact.
  Participation mixed with another family, reverse family order, missing,
  renamed, reordered, duplicated, substituted, or unknown targets fail before
  output;
- when HC1 was previously accepted, a return-resolution work order includes
  that HC1 canonical, manifest, and completion as its sealed return base. Only
  affected semantic target objects and their bounded collection-level proof
  values may change under the preceding derivation-claim rule. Every
  unaffected chapter agency contract and unrelated semantic array remains
  byte-for-value equal to that base. A
  first-attempt local revision has no return base; a partial base fails closed;
- the deterministic gate enforces the duty form and explicit lifecycle wording;
  fresh semantic review remains mandatory for euphemisms, hidden state claims,
  disguised design language, and conflicts with current HA1/HS1 authority.
  Producer validation is not semantic acceptance;
- capability, information, and permission checks use existing facts and reject
  unsupported action;
- `chapter_agency_contracts[]` covers HA1 chapter shells exactly once and in
  order; each item binds its parent unit, legal focal characters, named choice
  actors and/or source-bound institutional choice actors,
  cost bearers, unavailable characters, and an exact acquisition path for each
  focal character;
- an institutional choice actor records a natural role name, exact chapter
  source refs, its concrete responsibility, and its authority limit. Its refs
  must be bound by the chapter contract and by that chapter's HA1/HS1 authority;
  it cannot be used to disguise an unsupported action by a named character;
- unavailable characters are disjoint from focal and choice roles. They may
  remain cost bearers or affected subjects when authority supports that role;
- no element introduces biography, appearance, relation, feeling, ability, or
  information not present in authority;
- authority source classification and HLD ownership are never merged.

## Package behavior

The Agent session uses exact `actual_read_refs[]`; execution records the full
runtime read closure separately. The ready content package contains
`character-arc-placement.json`, session,
ordered evidence, execution, preview, deterministic validation, manifest, and
public completion. The manifest excludes itself and completion to avoid a hash
cycle. The single public stage-result envelope is package-external and contains
all required nullable fields.

`required_now` creates blocked/author_required before candidate publication.
A malformed, unsupported, or boundary-leaking candidate creates
revise/local_candidate. The skill submits affected evidence but never writes
the final owner, route, next state, or repair plan.

## Closed semantic bindings

`hc1-canonical.schema.json` is merged into the public SchemaCatalog before HC1 semantic checks. Every role, arc, relationship and feasibility element declares ownership and `resolution_ref`; a non-null value is legal only for an externally resolved `must_ask` and must exactly match its HDD allowlisted input. HB0 authority reconstruction, RFC 6901 derivation hashes, option-to-decision-to-projection bindings, and unique-solution exclusion evidence are hard checks. Session, five evidence artifacts, execution, validation and every non-ready artifact are closed-schema validated before packaging.
