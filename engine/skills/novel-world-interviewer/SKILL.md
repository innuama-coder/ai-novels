# 小说世界访谈

## 任务边界

产出 `world-operating-contract.md`，回答：**人物和事件在什么环境、规则、权力与信息条件下运行；这些条件如何限制行动、制造代价并保持自洽？** 世界不是背景百科，而是后续角色与因果设计可推演的运行条件。

开始前读取：

- [构思访谈共同协议](../../engine/docs/ai-novel-workflow/interview-protocol.md)；
- [conception-phase.md](../../engine/docs/ai-novel-workflow/conception-phase.md) 的共同交互协议；
- [world-methodology.md](references/world-methodology.md)；
- 生成交付物时读取 [world-operating-contract-template.md](references/world-operating-contract-template.md)。

只记录会改变人物选择、事件因果、事实可信度或读者对行动可行性的判断的信息。完整地图、谱系、术语、技术参数、语言系统或风俗清单若不承担这些作用，不属于本 skill。

## 输入、准入与权威

| 输入 | 使用方式 |
| --- | --- |
| `intent-card.md` | 必须 `ready`；继承故事承诺、主题问题、范围、硬边界、现实/虚构事实边界与作者授权。 |
| `subject-definition.md` | 必须 `ready`；继承核心选择、目标、代价、关系功能，以及主体需要的外部压力。它只提出世界需求，不预先拥有世界规则。 |
| 现实研究包 | 仅作为事实证据；作者须决定采用为事实、架空偏离或纯虚构前提。 |
| 作者补充材料 | 标记为作者输入，说明它改变哪个世界控制点后再纳入。 |

缺少任一必需输入、输入对故事范围或主体选择冲突、或关键现实主张没有作者采用方式时，输出 `blocked`，指出最小缺口。不得从旧世界观、下游故事线或聊天摘要补造规则。

世界访谈不改写 I0 的作品承诺，也不改写 I1 的主体选择。若某个主体选择在已确认世界前提下不可能成立，形成 `subject-revalidation` 回退包并退回 I1；不得在本 skill 偷改主体目标或代价。

## 访谈计划与状态

第一条实质问题之前，按 [novel-conception-interview harness](../../harnesses/novel-conception-interview/workflow.md) 创建 I2 会话目录和不可变 `plan.v1.json`。I2 固定八组、上限 30 题；本次必须写入精确总数与组配额。每次作者回答后立即追加 `events.ndjson`、运行验证器并重建报告。

使用 `exploring`、`awaiting_confirmation`、`confirmed`、`delegated`、`provisional`、`open`、`blocked` 表示决定状态；仅在所有必需组可交接时写 `ready`。`provisional + ready` 必须有作者接受的风险、影响范围与回看点。

## 世界决策组

### A. 世界前提与范围

确定故事发生的时空范围、相对现实的关键差异、适用尺度和不构建的范围。检查点：开发者能区分本书需遵守的世界前提与无需展开的背景。

### B. 运行规则、能力与代价

对每条关键规则建立：`条件 → 可做/不可做 → 成本或后果 → 例外 → 依赖的选择`。规则可以是物理、技术、法律、社会、超自然或心理现实；不得把“很危险”“技术先进”当作规则。

### C. 环境、空间与时间条件

只定义会改变进入、离开、行动、感知、资源或风险的关键环境、地点、基础设施和时间节律。场景布局、五感描写和物件生态属于开发阶段。

### D. 资源、机构、权力与责任

确定关键资源与能力由谁控制、谁有授权或执行权、如何验证/惩罚/规避，以及权力为何不能被简单绕过。检查点：任何关键行动都能解释权限和代价。

### E. 文化、日常与价值规范

确定会改变人物判断的社会常识、禁忌、阶层、家庭、行业、信仰或沟通规则，并说明普通人如何感知它、违规有何后果。不得把群体写成单一性格。

### F. 历史遗留与现时矛盾

只保留能写成 `过去事件 → 留下的结构 → 当前冲突` 的历史。年表、传说或设定资料若不影响当下选择，不纳入。

### G. 知识、信息与事实边界

确定谁知道什么、通过何种渠道知道、信息如何保密/失真/核验，以及现实事实、作者虚构和待研究内容的状态。信息何时向读者披露属于 I5。

### H. 压力推演、例外与一致性

从已确认规则推演：人物若不行动会怎样升级、常见捷径为何无效、例外为何不构成剧情便利。列出开放项、矛盾和需回退的唯一拥有者。

## 输出与完成条件

在写入 I2 `stage-completion.json` 前，生成并校验 `control-projection.json`。使用稳定的 `WLD-` ID，将世界定义、运行规律、资源与权力、信息边界、环境需求、限制、代价和开放项逐项无损投影。每项必须绑定 `world-operating-contract.md` 的精确行范围及文本哈希，并忠实标记 `hardness`。completion 使用 `contract_version: "2.0"` 并哈希绑定投影；专用 validator 未通过时不得交接。

投影中的每项控制必须只绑定世界稿中的一个完整 H2/H3 章节；`heading` 与字符串 `value` 分别原样对应章节标题和去除首尾空行后的正文。不得使用多段范围、局部摘录、结构化改写或哈希正确的近义转述。

按模板生成 `world-operating-contract.md`，包含：输入权威、世界前提、规则卡、关键环境、资源/机构/权力、文化规范、历史链、知识结构、压力推演、事实与例外账本、对角色/因果/叙述的交接，以及版本和状态。

本 skill 只能在 harness I2 中运行：会话写入 `<project>/interview-sessions/I2/<session-id>/`，先创建 `plan.v1.json` 并向作者说明精确问题数和预计时长；每轮立即追加 `events.ndjson`，运行验证器并重建 `report.md`。结束时生成世界运行契约和 I2 `stage-completion.json`。报告保留完整逐轮原文，设计契约只保留当前有效结论。

仅当以下条件全部成立时可写 `ready`：

1. 每条会改变关键行动的规则都有条件、限制/代价和例外处理；
2. 关键资源、权力、信息与责任能够解释重要行动为何可行或不可行；
3. 至少一条世界压力能写成“条件 → 限制 → 代价 → 被迫选择”；
4. 历史、文化和环境仅保留与当前选择有关的部分，且彼此不冲突；
5. 现实事实均有采用状态，未裁决的结构性问题已 `blocked` 或明确回退；
6. 完整访谈报告与当前有效契约版本一致。

## 交接与禁止项

交给 I3：角色实际可用的能力、资源、感知、社会规则、权力压力与信息边界。交给 I4：规则后果、升级机制、可用/不可用的解决路径和例外限制。交给 I5：故事世界中的信息通道、角色知识边界和事实状态。

不得输出人物履历或心理弧、触发/转折/高潮顺序、读者披露计划、场景列表、空间详细设计、对白或连续小说正文。发现上述问题时，按所有权路由至 I1、I3、I4、I5 或开发阶段。
