# 小说主体设计：方法论与落地规则

在开始主体访谈前阅读本文件。它的目的不是把人物写得“更丰富”，而是帮助 Agent 找到足以驱动因果故事线的主体、关系和压力。

## 可执行规则

### 把人物信息转成主体控制点

对每个候选主体，优先写下这个链条：

`它要达成什么 → 为什么现在必须行动 → 什么会阻止它 → 失败会失去什么 → 哪个认识/价值限制使选择困难`

其中任一项不能改变行动时，不把它放进主体定义。例如职业、口头禅、童年履历和外貌都可留给开发补足。

### 只保留有因果功能的关系

一条关系只有在以下至少一项成立时才进入交付物：

- 迫使主体在两个代价之间选择；
- 提供或剥夺达成目标所需的资源、信息、合法性或安全；
- 以相反目标、价值或认识形成持续压力；
- 让主体的行动代价变得可见。

“他们关系很好”“他很神秘”不是关系功能。

### 让世界成为压力，而非资料

只记录能写成下列句式的世界条件：

`由于 <规则/资源/时间/制度>，主体不能/必须 <行动>；若仍选择这样做，将付出 <代价>。`

不能形成这一链条的设定交给后续开发或世界设计，不在本 skill 展开。

### 访谈与确认

- 先问作者如何看待主体的选择，再讨论姓名、身份或候选关系。
- 候选最多三个，且仅在一个控制点上不同；每项说明会怎样改变目标、代价或压力。
- 作者直接确认的项标 `confirmed`；意图卡明确授权 Agent 决定的项标 `delegated`，不得伪称为作者确认。
- 对非人、群体或多主角，不强行套用“缺陷”或单一主角模型；改问其认识限制、价值冲突和承担代价的方式。

## 常见反例

| 不佳写法 | 为什么无效 | 改写方向 |
| --- | --- | --- |
| “主角是冷静的天才工程师，有悲惨童年。” | 没说明她会作何选择或为何不能放弃。 | “她必须保住系统控制权；承认异常会失去职业身份，隐瞒则使她成为伤害的一部分。” |
| “反派是强大的机构。” | 机构没有施压机制。 | “机构掌握访问权限；越权将失去行动资格，因此主体只能在服从与承担风险间选择。” |
| “他们互相喜欢又彼此误会。” | 关系没有改变主线。 | “一方掌握主体唯一的逃离资源，却要求主体做出违背核心承诺的交换。” |
| “世界观是高科技且危险。” | 设定没有改变行动代价。 | “系统日志不可撤销，因此每次帮助主体都会留下可追责的证据。” |
