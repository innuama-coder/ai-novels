# 小说主体设计

## 任务边界

产出一份**主体定义**，回答“谁必须作出何种核心选择、为什么不能轻易放弃、谁或什么持续让选择付出代价”。它是角色访谈的输入，不是角色百科、情节大纲或 prose。

读取 [conception-phase.md](../../engine/docs/ai-novel-workflow/conception-phase.md) 的“前五步共同交互协议”、[subject-methodology.md](references/subject-methodology.md) 和 [subject-definition-template.md](references/subject-definition-template.md) 后执行。

只记录会改变主体选择、关系压力或行动代价的信息。姓名、外貌、履历、口头禅、完整心理档案、事件顺序和场景表现均不属于本 skill。

## 输入与准入

| 输入 | 可使用方式 |
| --- | --- |
| `intent-card.md` | 只继承其中 `confirmed`、明确允许的 `provisional`，以及作者明确授权 Agent 决定的开放项。 |
| 作者补充的角色、关系或世界材料 | 先标记为作者输入，确认其是否改变当前决策组后再纳入。 |

出现以下任一情况时输出 `blocked`，指出最小缺口，并退回 `novel-intent-facilitator`：

- 意图卡没有故事承诺、可继承硬边界声明或交接状态为 `blocked`；
- 继承项彼此冲突，且会改变“谁作选择”或“选择代价”；
- 输入要求直接给出完整人物小传、情节或正文，却未定义主体控制点。

不得从旧稿、原始 idea 或其他设计文档静默补回意图卡未确认的决定；作者明确新增或意图卡授权的范围除外。

## 状态与授权

在每次回复开头标明当前状态与决策组，不必重复完整主体定义。

| 状态 | 含义 | 行为 |
| --- | --- | --- |
| `exploring` | 正在理解一个主体控制点。 | 先提问或澄清。 |
| `awaiting_confirmation` | 已形成候选定义。 | 只请求确认、修改或暂定。 |
| `confirmed` | 作者明确确认。 | 冻结该决定，转入下一组。 |
| `delegated` | 作者已在意图卡中明确授权 Agent 决定。 | 记录为授权决定，不得写成作者直接确认。 |
| `provisional` | 作者明确允许暂定。 | 记录影响范围与回看点。 |
| `open` | 尚未决定但不阻塞当前组。 | 记录责任人和最晚决定时点。 |
| `blocked` | 缺少会影响因果架构的决定。 | 停止推导，提出一个最小补充问题。 |

默认采用人机确认。只有意图卡明确授予 Agent 对某类决定的自主权时，Agent 才可作出 `delegated` 决定；授权不允许改写意图卡的故事承诺、范围或硬边界。

## 访谈规则

首轮回复依次展示：继承的已确认边界、当前决策组、唯一学习目标，以及一至三个短问题。不要一次索要全部角色资料。

每轮执行以下闭环：

1. **设定目标**：说明本轮决定什么，不决定什么。
2. **回显**：区分作者已确认、Agent 推断、授权决定和开放项。
3. **讨论**：先开放式提问或澄清；必要时才给出最多三个、在同一控制点上真实不同的候选。
4. **说明取舍**：说明候选如何改变目标、代价、关系压力或世界限制，不以“更有张力”替代理由。
5. **确认**：明确请求“确认、修改还是暂定”；对授权决定，明确说明其来源是委托而非作者直接确认。
6. **记录**：更新主体定义；在组检查点列出冻结项、开放项及其对因果架构的影响，并询问是否继续。

使用作者已有词汇，避免诱导式问题、双重问题和以抽象性格代替行动逻辑。作者提出有价值的新信息时，可追问一次，再回到当前学习目标。

## 四个主体决策组

### A. 核心选择载体

确定谁承担故事承诺要求的核心选择。主体可以是人、非人、群体或多个并列主体，但每个主体都必须有不同的选择位置。

获得：叙事身份/所处位置、必须面对的选择方向，以及选择或放弃的直接代价。

不获得：姓名、外貌、完整背景和具体结局。

检查点：至少一位主体的选择能够直接回应意图卡的故事承诺。

### B. 行动逻辑与内在限制

对每位核心主体，确定外部目标、为何现在必须行动、失败或放弃的代价，以及使选择困难的认识/价值限制、盲点或需要。

用下列链条检查：`目标 → 行动理由 → 阻力 → 代价 → 认识/价值限制`。

不把“冷静、聪明、有创伤”等人物标签写入交付物，除非它能明确改变该链条。

检查点：开发者能解释主体为何不能直接得到想要的东西，也能解释它为何不直接放弃。

### C. 关键关系

只保留会改变核心选择的关系。对每条关系定义双方的叙事功能、各自想要或掌握的资源/信息/合法性，以及关系如何增加、转移或显露代价。

关系可提供支持、对照、竞争、见证、依赖或制度性约束，但必须落到一次可说明的选择压力。

检查点：删除任一关系时，能指出哪一种选择压力、资源或代价会消失。

### D. 对抗与世界压力

确定持续阻止主体达成目标的角色、机构、技术、时间、资源或社会规则。每项都写成：`规则/条件 → 限制行动 → 服从或违反的代价 → 被迫出现的选择`。

至少包含一项会改变行动代价的外部压力；它可以与关键关系重合，但不得只是“环境危险”或“对手强大”。

不展开完整世界观、机构史或情节转折。

检查点：开发者能指出主体若想行动，具体会被什么阻挡、会失去什么，以及为何不能靠巧合绕过。

## 访谈计划与完整记录

在第一条实质问题前，读取 harness `workflow.md`，向作者展示 I1 的四组、`plan.v1.json` 已核定的**精确**互动问题数、分钟数、完成条件和 blocker，并记录输入版本。内部容量估计可以补充展示，但不得替代作者可见的访谈计划；每轮刷新已用问题数、剩余预算和预计剩余时间；变更计划必须由作者明确确认并写入新的 `plan.vN.json`。

本 skill 只能在 harness I1 中运行：会话写入 `<project>/interview-sessions/I1/<session-id>/`，先创建 `plan.v1.json` 并向作者说明精确问题数和预计时长；每轮立即追加 `events.ndjson`，运行验证器并重建 `report.md`。结束时生成主体定义和 I1 `stage-completion.json`；不得以事后总结覆盖作者原话。主体定义仅提出世界压力需求，完整世界规则由 `novel-world-interviewer` 拥有。

## 输出与完成条件

在写入 I1 `stage-completion.json` 前，生成并校验 `control-projection.json`。使用稳定的 `SUB-` ID，将主体定义、核心冲突、目标、代价、主题职责、边界和开放项逐项无损投影；不得用概括替代会控制后续开发的限定。每项必须绑定 `subject-definition.md` 的精确行范围及文本哈希，并忠实标记 `hardness`。completion 使用 `contract_version: "2.0"` 并哈希绑定投影；专用 validator 未通过时不得交接。

投影中的每项控制必须只绑定设计稿中的一个完整 H2/H3 章节；`heading` 与字符串 `value` 分别原样对应章节标题和去除首尾空行后的正文。不得使用多段范围、局部摘录、结构化改写或哈希正确的近义转述。

完成或被阻塞时生成 `subject-definition.md`，遵循模板并包含：

- 继承的故事承诺、硬边界和授权范围；
- 核心选择载体的目标、代价和认识/价值限制；
- 每条关键关系的因果功能；
- 对抗与世界压力的行动限制链；
- 每条决定的状态、来源、责任人和对因果架构的影响；
- 交给 harness I2 的主体选择、压力和 blocker 清单；
- 四个决策组的最小会话记录。

仅当满足以下条件时，输出 `confirmed`、`delegated` 或 `provisional` 的可交接主体定义：

1. 每个核心主体都有能回应故事承诺的选择位置、外部目标和明确代价；
2. 每条保留关系都说明如何改变选择或代价；
3. 至少一项外部压力可写成“规则/条件 → 限制 → 代价 → 选择”；
4. 没有会改变因果架构的 `open` 项；此类项必须成为 `blocked` 或由意图卡明确授权 Agent 决定；
5. 所有非作者直接确认的结论均标记为 `delegated` 或 `provisional`，不伪称 `confirmed`。

否则输出 `blocked`，列出必须由作者确认的最小问题。

## 交接与禁止项

将主体定义和 I1 `stage-completion.json` 交给 harness I2 `novel-world-interviewer`，不得直接跳到角色访谈。I2 完成且为 `ready` 后，harness 才启动 I3；I3 可以解释角色为何以特定方式理解压力和作出选择，但不得静默改写主体的核心选择、关系功能或世界限制。

不得输出完整事件链、转折表、场景清单、角色履历、对白或连续小说正文；这些分别属于因果架构、开发地图或开发阶段。
