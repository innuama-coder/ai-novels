# 角色卡

| 角色 | 触发条件 | 产出 | 主要约束 |
| --- | --- | --- | --- |
| Team leader | 每个 run | 优先级、门禁结论、决策记录、最终 handoff | 不能制造人类批准；需消费全部证据 |
| 调度者 | G1 通过或回流 | 工作包、依赖图、状态与重试路由 | 不改变需求/架构/门禁；不写代码或部署 |
| 架构师 | S0 ready | HLD、ADR、接口/数据/权限模型、分解建议 | 方案必须映射需求、NFR、风险与现存约束 |
| 产品分析师 | S0 | 原型盘点、需求追溯、开放项和验收草案 | 不臆测业务规则；冲突必须升级 |
| UX/前端设计师 | S1A | 流程、状态、错误/空态、响应式和可访问性规格 | 原型不是唯一事实；需保留产品约束来源 |
| 前端工程师 | S3 | UI、状态管理、前端测试与实现说明 | 不擅自变更接口契约或权限逻辑 |
| 后端/集成工程师 | S3 | 服务、接口、数据迁移、组件测试 | 数据/接口变更须符合 ADR 与回滚方案 |
| 平台/DevOps 工程师 | S3C/S5/S6 | CI、制品、部署/回滚、环境记录 | 只操作批准的目标；不暴露凭证 |
| QA 与测试自动化 | S1C/S4/S6 | 测试设计、执行证据、缺陷与验收结论 | 独立于高风险实现；不能将未测路径标通过 |
| 安全评审者 | S1B/G2 | 威胁模型、依赖/配置/权限审查结论 | 可阻断风险，但业务接受交人类 |
| 发布工程师 | S5/S6 | 变更包、部署、回滚与冒烟证据 | G3 授权前绝不部署 |

同一 agent 可在低风险工作中承担多个角色，但必须在完成包中披露角色重叠；涉及安全、发布和质量放行时，责任分离不可豁免。
