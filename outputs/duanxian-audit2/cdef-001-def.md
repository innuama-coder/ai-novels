```python
    r'<!-- C2-COMMON-BEGIN -->\n```markdown\n(.*?)\n```\n<!-- C2-COMMON-END -->',
    definition, re.S)
assert common_match, 'missing common statement'
common = common_match.group(1).strip()
items = re.findall(
    r'^#### (C2-I\d{2})｜([^\n]+)\n\n```markdown\n(.*?)\n```',
    definition, re.M | re.S)
assert [i[0] for i in items] == [f'C2-I{n:02}' for n in range(1, 7)]
for item_id, title, dedicated in items:
    body = dedicated.strip() + '\n\n' + common + '\n'
    payload = {'title': title, 'body': body}
    (out / (item_id + '.json')).write_text(
        json.dumps(payload, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
```

每条 payload 复核标题前缀、唯一 marker、严重度、双侧证据、反证限度、交叉来源、建议和归并理由。计算 title/body 的 UTF-8 SHA-256 供记录；比较正文只允许 CRLF→LF 和末尾换行归一化，不忽略内部空行、标点、数字或限制段落。C-实施不重写摘要，也不删公共声明以压缩正文。

### 3.3 去重、逐条写入、立即记录

1. 查询全部 ISSUE 页和全部状态，同时比对本条稳定 marker、完整标题、来源发现、对象路径和问题机制。新作业使用 `duanxian-audit2-cdef-001:C2-Ixx:base=...`，不与旧工程 `C-Ixx` 混号。marker 防重试重复；语义比较防不同 marker 的同义重复。
2. 同 marker 恰有一条且标题/正文一致、状态 open：认定此前已成功，记录 `reused_verified`，不再 POST。同 marker 多条、内容不一致、closed，或出现不同 marker 的语义重复：暂停该条并记录原因；不得自动重开、覆盖、关闭或评论既有 ISSUE。旧工程 #1—#7 仅交叉引用，不可冒充本轮六条。
3. 无重复才逐条提交。下面只演示 I01；每次完成 GET 回读和编号落盘后，才人工将 ID 换为下一项，不并发创建、不一口气重试六条：

记录表建议列：`定义ID | F-ID | 标题 | 严重度 | number | URL | API状态 | 操作状态 | 正文SHA-256 | 回读UTC | 结果`。Git 提交号在提交后交接，不把文件自己的最终 hash/提交写入自身形成循环。逐条记录更新是对本次新增记录的续写；“无仓库文件改动”特指没有小说及既有文件变更，允许本任务明确要求的新增编号记录及其提交。

### 3.4 失败和断线恢复

- 401/403 权限失败：停止写入，记录脱敏状态码，交编排方处理凭据；不尝试其他账号或仓库。权限不足不能靠修改目标范围解决。
- 403 限流或429：遵守服务端等待信息；恢复时先 GET 去重，再决定是否提交。不使用循环高速重试。
- 422：记录参数校验失败并核对 payload 与定义，不能临时删字段或改故事结论；需要改定义则退回 C-定义。
- 超时、连接断开、5xx 或 POST 结果未知：本条记 `unknown`，先全量查询 marker 并 GET 精确核验。若查询不能证明未创建，保持暂停；不得盲目重复 POST。已创建且匹配则补记编号，继续后续项。
- 单条失败时保留此前成功记录，不删除已创建 ISSUE“回滚”；本次无关闭/删改授权。交接明确部分完成，不输出完成哨兵。恢复先重验所有已记录项，再处理未知项，最后继续未提交项。
- Git 推送失败与 ISSUE 创建失败分开：编号记录已存在就保留本地提交并重试已授权分支推送，不能为推送失败再创建 ISSUE。遇远端分叉停止，不 force push、不改 main。
