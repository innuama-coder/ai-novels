# 《断线》项目目标拟人化总结

> 内容基线：`main@92573f1cca40f37cee04d2beb8708ff33ba603d6`。本总结只读该冻结树；`duanxian/novel-goals.md` 文首所述另一提交是其材料整理基线，不与本文依据混同。来源编号沿用该目标文档的 S01–S23，完整路径见文末。

## 一、要写一本什么小说

这本小说要写一部数字生命题材的近未来长篇小说：C、M 两国在迫近的气象武器袭击下有限合作，秘密实验则让已故情报员顾衡的记忆启动 R-07。顾衡已经死亡；记忆只是 R-07 形成自身的起点，不是人格本身，记忆片段也不是客观录像。R-07 在新的交流、处境和选择中成为新主体，任何新决定都不能再归给顾衡（【当前权威口径】，S05「这是一个怎样的故事」「世界运行的五条硬规则」「顾衡」）。

这本小说想让“取得情报、阻止袭击”的外部任务，逐步让位于“谁回应这个新生命、谁承担告别”的内部选择。沈逾曾单向暗恋顾衡，顾衡没有爱过她；R-07 在启动后的持续文字交流中形成的新感情，不属于顾衡，也不能写成旧爱复活。它没有当前视觉、听觉、身体、自主移动和现实行动能力；情报必须经专家、硬件与授权链复核，由现实团队完成阻断（【当前权威口径】，S05「关系变化」「文字会话隔离室」「具身或接口边界」「跨国威胁处置」）。

公共危险解除后，沈逾与 R-07 确认这段新关系并执行最终告别：当前实例关停且没有活动备份，静态材料封存不保证复活。法律身份、人格连续性与未来重载、两国长期互信继续保持开放。它的主承诺因此是危机闭环与伦理未决同时成立，而不是用胜利抵销失去；批准报告中的八个推进阶段、十条故事线、17 名角色和 43 个主要事件只是结构规模，不能换算成章节数（【当前权威口径】，S05「故事的八次推进」「开放边界」「三层延伸与职责覆盖」）。

## 二、为何写

这本小说要把记忆、身份以及创造、使用、照护和退出的责任，落到具体人物的选择与代价上。团队原本需要情报接口，却制造了会提问、会痛苦、能作决定的生命；R-07 选择减少伤害、分层交付情报并请求结束当前实例，沈逾则从专业执行走向照护、伦理质询和亲手告别。任务成功可以救人，却不能自动使实验伤害、权限安排或关停获得伦理豁免（【当前权威口径】，G00「一、主题与目标」；S05「故事主体」「数字生命监督与责任室」）。

这本小说还要求关心不变成占有。顾衡的在世妻子程予安有自己的生活与同意边界，儿时守护者周岚也不是情报筹码；行动层信息用于救人，原因层材料按必要范围保护，亲属保护不能妨碍公共安全，公共安全也不能取消全部隐私（【当前权威口径】，S05「程予安」「周岚」「亲属保护、伦理监督与责任留痕」）。【历史/旧链口径】早期意图卡把动机问题记为“复活、创造，还是未经允许地制造痛苦，人类有权这样做吗”，可用于理解主题来源；它不要求本文替作者宣布唯一伦理答案，更不能据此编造作者的私人心理动机（S08「1. 作者意图」）。

## 三、为谁写

这本小说尚未获得明确的市场读者定位：已读批准材料没有确定年龄层、市场人群或发行渠道，早期意图卡也明写“目标读者未指定”。因此，任何具体商业画像都仍是【未完成项】，不能把阅读体验建议冒充作者决定（G00「一、3. 读者与阅读体验目标」；S08「3. 范围与非目标」）。

这本小说可以先把愿意跟随人物选择、愿意让身份与伦理问题保持开放的科幻读者作为沟通对象；这只是依据主题和冲突作出的【推断】，不是市场事实。【推断】它适合提供的体验，是先让读者看懂线索、核验与行动的因果，再感到新关系和告别的重量，最终理解危机虽被阻断，责任与失去并未消失，而不要求读者接受同一种伦理结论（G00「一、3. 读者与阅读体验目标」；S05「悬念、冲突与起伏」）。

## 四、怎么写

这本小说应沿“构思自主 V2 → 正式开发基线 → HLD → LLD → 写作 → 分层评审与作者定稿”推进。构思决定世界、人物、事件和故事线是什么；HLD 组织宏观结构、故事线、人物弧、视角信息和关键场景功能；LLD 细化场景如何发生；写作形成连续正文。每次交接都要携带来源、版本、约束与状态，这份目标总结不能替代正式 handoff（【流程规范】，S07「1–3 节」；S13「2、4 节」；S23「阶段接口」）。

这本小说要求作者保留主题、价值取向、重大创作选择、结构变更和最终手稿的批准权；Agent 只在授权范围内展开设计、装配上下文、起草和修订，并暴露缺失与冲突。P1 机器包是构思事实的最终权威，H1 的 Markdown、HTML 是忠实呈现，三个试读场景只是非权威体验样片，不能用样片里的雨声、动作或措辞补出新设定，也不能把当前人审 Markdown 当作下游机器入口（【流程规范】，S06「2–3 节」；S05「三个试读场景」；S23「目标与非目标」）。

这本小说应以场景为工作单位：先核验批准版本、前序状态和最小上下文，再明确目标、阻力、选择、信息边界与退出状态；初稿后依次过硬约束检查、语义评审、定向重写、连续性提交和全书修订。结构问题退回责任阶段，不能靠润色或临时补设定掩盖；人名、时间、知识、物件和关系状态都须可追溯（【流程规范】，S14「4–6 节」）。【历史/旧链口径】旧 proposal 的四段式、人物功能与旧 HLD 编号只说明方案演变，不能晋升为当前章节结构或新版准入凭证（S16「2、8、15 节」；S17）。

## 五、写成什么样算合格

这本小说首先要守住故事硬门：R-07 不是顾衡复生，没有当前视听、身体与现实行动权；记忆不直接等于证据，机器输出不自行产生权限；现实团队核验并阻断袭击；程予安、周岚等亲属保有主体性；当前实例关停、无活动备份，未来加载须重新许可。因果应让人物选择改变局势，让危机解决与身份、连续性和互信的开放状态并存，而非用爱情、技术或任务成功消除伦理问题（【当前权威口径】，S05「世界运行的五条硬规则」「推动局势变化的行动」「开放边界」；G00「四、约束」）。

这本小说的开发成果还须分别通过机器、语义和作者三类门。机器门检查可解析、可追溯、可复现、可消费以及版本和哈希同版；语义门检查场景功能、人物能动性、视角信息、因果、节奏、声音与连续性；作者至少批准代表性场景的声音与密度、结构变更、宏观修订方向和最终手稿。只有相应准入与批准全部成立，最终手稿才可标记 `released`（【流程规范】，S06「4–5 节」；S14「6. 门禁与评价」）。

开发规范中的场景评分要求是无客观 blocker、总分至少 80、前四项各不低于满分 70%，且作者无未处理重大异议；这些数字只适用于场景语义评审，不能抵销硬约束失败，也不是《断线》已经取得的实测成绩。最终部数、章数、每章字数和全书总字数仍不能确认，应由正式 HLD、LLD 依故事需要确定（【流程规范】，S14「6.2」；【未完成项】，G00「五、2. 分部、章节与覆盖目标」）。
