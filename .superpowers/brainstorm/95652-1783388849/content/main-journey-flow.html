主流程总览 · 从 idea 到第一个任务

把已经设计过的页面串成完整路径：用户输入 idea，AI 对齐需求，确认需求表，选择工坊/专家，创建项目，并进入第一个任务。

鲲工坊 KUNORA.AI · 主链路
用户主路径
默认路径以普通用户熟悉的输入、对话、确认、查看进度为主，专业对象在系统内部逐步建立。
已登录后体验
界面流转
1. 登录后首页
输入 idea
用户从大 Logo 首页输入自己的想法，也可参考专业方向样板。
↓ 交给 AI 助手
2. Intake 工作台
对话 + 需求表
左侧 AI 追问，右侧需求表实时形成并可直接修改。
↓ 用户确认需求表
3. 选择工坊/专家
需求展示 + 选择
主视图上方展示确认后的需求，下方选择匹配的工坊/产品专家。
↓ 创建项目与第一个任务
4. 项目页面
项目 + 多任务
项目绑定一个需求表，显示执行中任务、已完成任务，并支持新建任务。
↓ 打开任务
5. 任务页面
渐进式任务详情
默认展示工作流状态和当前环节摘要；交付物、日志按需展开。
系统对象状态
Idea
由首页输入产生，是最原始的用户表达。
Requirement Table
确认前：独立存在，绑定 idea。确认后：仍绑定 idea，同时绑定项目。
未确认 已确认
Workshop / Expert
确认需求后选择匹配工坊或产品专家。工坊包含产品、开发、测试、验收专家。
Project
由已确认需求表创建。一个项目绑定一个需求表，并绑定一个工坊。
Task
项目下可以有多个任务。每个任务独立执行设计、开发、测试、验收，并产生交付物与处理日志。
Deliverables / Logs
交付物和日志属于任务环节。默认不全量展示，按需打开。

主链路规则

用户体验

  • 用户只需要输入 idea、确认需求、选择工坊/专家、查看项目和任务。
  • 专业对象的建立发生在系统背后，通过界面状态自然表达。
  • 项目页和任务页都采用渐进式信息展示，避免信息墙。

对象边界

  • 需求表确认前不属于项目。
  • 项目绑定一个已确认需求表，可以包含多个任务。
  • 任务内部才有设计、开发、测试、验收及对应交付物和日志。
